# VRC7a 向けファミコン移植基盤の開発プラン

プロジェクトの背景は、アーケード版『魔界村』をファミコンへ移植したいという構想にある。この計画では、Mesen の NTSC 設定でビルドから動作確認まで完結する VRC7a の移植基盤を整える。2つの試験コースで起動、描画、入力、地形判定、状態遷移、音声を検証する。開発成果物は診断用の `.nes`、Mesen 自動試験、再現手順とする。

## 開発・動作環境

| 項目 | 構成 |
| --- | --- |
| 動作確認 | Mesen の NES・NTSC 設定。1P コントローラーを使い、スプライト制限を有効にする。対応バージョンをリリース時に記録する。 |
| ROM 形式 | NES 2.0 の Mapper 85／Submapper 2。検証基準は PRG-ROM 512 KiB、CHR-RAM 8 KiB、WRAM 8 KiB。32 KiB 版も回帰試験で使う。 |
| プログラム | 6502 系のネイティブコード。PRG は 8 KiB 単位で切り替え、リセット処理と NMI・IRQ ハンドラを `$E000–$FFFF` の固定バンクに置く。 |

[実基板の部品構成と写真](https://nescartdb.com/profile/view/3951/lagrange-point) · [VRC7a のバンク構成とレジスタ](https://www.nesdev.org/wiki/VRC7) · [NES 2.0 ヘッダー仕様](https://www.nesdev.org/wiki/NES_2.0)

## 調査ツールの使い分け

国内版 Revision G の調査結果は技術資料として参照できる。基盤の変更は Mesen で試験 ROM を実行し、観測した画素、レジスタ、フレーム数などで検証する。[国内版 G の計測結果と再現手順](docs/revision-g.md) · [6809 ROM マップ](docs/revision-g-rom-map.md)

- アーケード基板の挙動を参照する際は、`mame -rompath reference -verifyroms makaimurg` で ROM セットを照合する。メモリマップと描画順は公開ドライバを参照し、実行時のレジスタ書き込みは必要に応じて MAME のデバッガーで観測する。[MAME のコマンドライン仕様](https://docs.mamedev.org/commandline/commandline-all.html#verifyroms) · [MAME デバッガー](https://docs.mamedev.org/debugger/)
- REA は、ビルド済みの試験 ROM や実行時の状態を調べる必要があり、Mesen の試験とソースだけでは原因を絞れない場合に使う。

## 次の開発マイルストーン

512 KiB版の両コースで、初回と途中復帰後の射撃音が Mesen のミックス出力に含まれ、途中復帰・クリア・メニュー復帰の前後で伴奏が続くことを波形で確認した。元のコースの初回射撃は、比較用 WAV の試聴でも伴奏の中で聞き取れた。[コース音声の比較試聴](#コース音声の比較試聴)

## Mesen 用の試験パッケージ

```powershell
./tools/package-vrc7a-trial.ps1 -Mesen
```

両版の診断 ROM を再ビルドし、`build/vrc7a-mesen-trial.zip` に操作手順、ROM の SHA-256、Mesen 回帰試験をまとめる。展開先では手元の Mesen 2.1.1 を指定して、cc65 やソースツリーなしで試験を再実行できる。[展開後の操作と試験手順](docs/vrc7a-mesen-trial.md)

## Mesen の回帰試験

Mesen 2.1.1 で NES の地域を NTSC にし、1P に NES コントローラーを割り当てる。地域の自動設定でも、この試験 ROM のヘッダーに従って NTSC になる。スプライト制限を有効にし、NTSC のオーバースキャンを上下左右とも 0 にして 256×240 の画面を使う。設定を保存してから、PowerShell で次を実行する。

```powershell
./tools/test-mesen.ps1
```

既定では `build/mesen/Mesen.exe` を使う。別の場所にある場合は `-MesenPath` で指定し、試験ごとの制限時間は `-TimeoutSeconds` で変更できる（既定は120秒）。cc65 の場所は `-Cc65Bin` で指定できる。

32 KiB 版と 512 KiB 版を再ビルドする。32 KiB 版では診断系の試験、512 KiB 版ではアーケードモードと従来の2コース連続プレイの試験を実行する。失敗やタイムアウトがあれば該当する ROM 名と試験名を表示し、残りの試験も実行してから終了コード 1 を返す。Mesen の標準出力と標準エラーは `build/mesen-smoke/` に試験ごとに保存する。

### 512 KiB 版のコース検証

リポジトリのルートで `./build.ps1 -Hardware` を実行し、上記の設定の Mesen 2.1.1 で `build/vrc7a-test-512k.nes` を開く。FM 6声と APU の伴奏が始まってからコースに入る。

**連続プレイ**では、タイトルで **上＋START** を押すと元のコースから始まる。初期残機はプレイ中の1機を含む3機、制限時間は各コース120秒。HUD の `STG`、`LIFE`、`TIME` に現在の値を表示し、途中復帰地点を通過すると `CP` が `N` から `Y` に変わる。

被弾か時間切れで1機失う。残機があれば **START** で途中復帰地点かコースの入口から制限時間を戻して再開する。1コース目の `COURSE CLEAR` で **START** を押すと残機を引き継いで次へ進む。`FINAL CLEAR` または `GAME OVER` で **START** を押すか、途中で **SELECT** を押すとタイトルに戻る。通しプレイ、途中復帰、時間切れ、残機切れ後の新規開始は `tools/mesen/campaign-smoke.lua` で確認できる。

**個別に診断する場合**の手順は次のとおり。

1. **B** で元のコースに入る。**上** で負荷試験用の印を出し、右へ進む。上り段では右を押したまま **A** で跳び、最初の敵と同じ高さに来たら接触する前に **B** で撃つ。ひし形の標識を越え、窯の火花は **A** で飛び越えて、右端の旗の前に着地する。`COURSE CLEAR` が出たら **SELECT** でメニューに戻る。
2. **下を押しながら B** で追加コースに入る。同じ操作で標識を越え、窯と同じ高さの段の左端で止まる。そこで火花を受け、**START** で標識の右に復帰する。右に跳びながら、窯と高さが合ったところで **B**。旗の前で着地してクリアする。クリア後の **START** で追加コースの最初に戻り、**SELECT** でメニューに戻る。

入力を自動で再現する場合は、ビルド後に次を実行する。元のコースのメニュー経路と、負荷を掛けた通常クリア・途中復帰の両経路、追加コースの途中復帰からクリアとバンクの切り替えを確認する。

```powershell
./build/mesen/Mesen.exe --doNotSaveSettings --testRunner --timeout=50 tools/mesen/course-menu-smoke.lua build/vrc7a-test-512k.nes
./build/mesen/Mesen.exe --doNotSaveSettings --testRunner --timeout=50 tools/mesen/course-clear-smoke.lua build/vrc7a-test-512k.nes
./build/mesen/Mesen.exe --doNotSaveSettings --testRunner --timeout=50 tools/mesen/course-bank-smoke.lua build/vrc7a-test-512k.nes
```

| 計測対象 | 32 KiB 版 | 512 KiB 版 |
| --- | ---: | ---: |
| 元のコースの行・列同時更新＋DMA | 1,843 | 1,843 |
| 元のコースで途中復帰した後のプレイ中の最大 | 1,355 | 1,355 |
| 追加コースの行・列同時更新＋DMA | 1,842 | 1,842 |
| 追加コースで上記に FM 6声と APU の伴奏・射撃音が重なったフレーム | 1,841 | 1,841 |
| 追加コースで途中復帰した後のプレイ中の最大 | 1,356 | 1,356 |

単位は CPU サイクル。Mesen の走査線241の先頭から OAM DMA 開始までの PPU ドット数を3で割って切り上げ、DMA の最大514サイクルを加えた。画面を消して行う再描画は集計から外した。追加コースでは行40バイトと列27バイトの同時転送、走査線31の HUD 切り替え、上端32 px の画素を確認した。窯の火花が出たとき、同じ走査線に13枠が並び、火花と印3個の画素が表示された。

両コースで CHR-RAM のパターンを共有する。32 KiB版は文字・HUD 432バイト、512 KiB版は残機と時間の数字を含めて592バイトを使う。両版とも地形は176バイト、スプライトは256バイト。総使用量は32 KiB版で864 / 8,192バイト、512 KiB版で1,024 / 8,192バイト。ビルド時に内訳が出る。

### 512 KiB 版のステージ背景ビューア

タイトルで **SELECT** を押して `VRC7A TEST MENU` を開き、**上＋A** で `STAGE VIEW` に入る。既存のステージ1から始まり、十字キーで背景をスクロールできる。**A** で次、**B** で前のステージへ切り替える。ステージ1と7の間は循環し、切り替えるたびにカメラはマップ左上に戻る。**SELECT** でテストメニューに戻る。

プレイ時と同じ背景タイルとパレットを読み込み、プレイヤー、敵、HUD を表示せずに地形を確認できる。回帰試験は `tools/mesen/arcade-stage-view-smoke.lua`。

### 512 KiB 版のサウンドテスト

タイトルで **SELECT** を押して `VRC7A TEST MENU` を開き、**下＋A** で `SOUND TEST` に入る。

| 操作 | 動作 |
| --- | --- |
| 左／右 | BGM 1〜7を選ぶ。左が前、右が次。 |
| 下／上 | SE 1〜3を選ぶ。下が前、上が次。 |
| A | 選択したBGMを先頭から再生する。 |
| B | 選択したSEを鳴らす。再生中のBGMに重ねて確認できる。 |
| START | BGMとSEを停止する。 |
| SELECT | 音を止めてテストメニューへ戻る。 |

BGMは1から順に開始、ステージ1・2、ボス、クリア、ゲームオーバー、ステージ3・4、ステージ5・6。SEは1から順に射撃、被弾、鍵取得。番号の選択は両端で循環し、再生中に番号を変えても再生は続く。回帰試験は `tools/mesen/arcade-sound-test-smoke.lua`。

### マニフェストのエリアビューア

`./build.ps1 -Hardware -AreaManifest <マニフェスト.json>` で生成した `build/vrc7a-test-512k-areas.nes` を Mesen で開く。タイトルで **SELECT** を押し、テストメニューの **左＋A** でエリアビューアに入る。

**左／右** で前／次のエリア、**下／上** で前／次のポーズを選ぶ。選択は両端で循環し、エリア切り替え時は先頭のポーズを表示する。**SELECT** でテストメニューへ戻る。[マニフェストの作り方](docs/stage-design.md#37-エリアの画像データを-prg-rom-に配置する)

### マニフェストの試験コース

付属の2つの試験コースをビルドから自動検証するには、Python と Pillow が入った環境で次を実行する。平坦コースでは、両敵の撃破、ページ境界を越える敵弾の命中、チェックポイント復帰、ゴールとメニュー復帰を確認する。段差コースでは、歩行時の壁判定、ジャンプでの上段への着地、下段への落下、被弾後の上段への復帰、ゴールを確認する。

```powershell
./tools/test-mesen.ps1 -AreaTrial
```

入力は `build/area-trial-fixture/` に生成される。平坦コースは `stage.json`、段差コースは `steps.json` で、どちらも `areas.json` を使う。手動で段差コースを遊ぶ場合は、次のようにビルドする。

```powershell
./build.ps1 -Hardware -AreaManifest build/area-trial-fixture/areas.json -AreaTrial build/area-trial-fixture/steps.json
```

`build/vrc7a-test-512k-areas-trial.nes` を Mesen で開く。タイトルで **SELECT** を押し、テストメニューの **左＋B** で試験コースを始める。左右で移動、**A** でジャンプ、**B** で射撃、被弾後は **START** で再挑戦する。**SELECT** でテストメニューに戻る。試験コース JSON の `player_poses` でプレイヤーの画像、`enemies` で固定敵と射撃敵の位置を指定できる。[試験コース JSON の条件](docs/stage-design.md#38-エリア-bg-を試験コースに組み込む)

### コース音声の録音と測定

Windows x64 の Mesen 2.1.1（`137ae7c`）の内蔵レコーダーを使う。録音用スクリプトは NTSC、1P に NES コントローラー、マスター音量と各音源100%、パン中央、EQ・リバーブ・クロスフィード無効の条件で実行する。各コースを電源投入から走らせ、被弾後にチェックポイントから再開し、クリア画面から SELECT でメニューに戻る。

```powershell
./build.ps1 -Hardware
python tools/record-course-audio.py original
python tools/record-course-audio.py alternate
python tools/record-course-audio.py original --mute-shot
python tools/record-course-audio.py alternate --mute-shot
python tools/measure-audio.py build/audio/course-512k/original.wav build/audio/course-512k/alternate.wav
```

既定では `build/mesen/MesenCore.dll` を使う。`--core` で同じ版の別の場所を指定できる。WAV とイベントのフレーム番号を `build/audio/course-512k/` に保存する。`--mute-shot` では同じ ROM と入力で、APU パルス2の音量だけを Lua で0にする。[録音スクリプト](tools/record-course-audio.py) · [入力とイベント記録](tools/mesen/course-audio.lua)

測定に使った `vrc7a-test-512k.nes` の SHA-256 は `70046c0a3506bf8852602f383b48c90dd454d6fb5104b0320546f9152662b1f2`。48 kHz・16ビット PCM で、両チャンネルのサンプルは一致した。

| コース | 全体の RMS / ピーク (dBFS) | 最初の射撃 | 途中復帰 | クリア | メニュー復帰 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 元のコース | −29.08 / −16.22 | 6.90秒 | 15.82秒 | 16.94秒 | 17.57秒 |
| 追加コース | −29.06 / −15.45 | 5.92秒 | 15.24秒 | 16.47秒 | 17.64秒 |

通常録音と射撃音を消した録音でイベントのフレーム番号は一致した。通常録音でクリッピングに達したサンプルは0。射撃の開始前17 msから開始後115 msまでの区間で、両録音の差分 RMS は約 −39 dBFS、射撃音を消した伴奏の RMS は約 −28〜−30 dBFS だった。途中復帰後の射撃でも差分が出た。被弾・途中復帰・クリア・メニュー復帰の各前後125 msでは、両録音が一致し、連続した無音もなかった。

### コース音声の比較試聴

前節の4本の録音を用意してから次を実行する。イベントログを照合し、両コースの初回射撃と途中復帰後の射撃の比較用 WAV を `build/audio/course-512k/*-shot-ab.wav` に生成する。

```powershell
python tools/prepare-course-listening.py
```

各 WAV は、射撃音を消した1秒、0.6秒の無音、通常録音の同じ1秒の順に並ぶ。PCM は元の音量のまま切り出す。後半が始まって約0.65秒の射撃音を、普段のプレイ時と同じ再生音量で確認できる。ミックスを変更したときは、同じ箇所を再録音して比較できる。

## 1. 起動と拡張音声

Windows PowerShell から `./build.ps1` を実行すると、`build/vrc7a-test.nes` が生成される。確認に使ったツールは ca65／ld65 V2.19（Git `52727a5`）。`PATH` 上のツールを使い、見つからなければ `%USERPROFILE%\tools\cc65\bin` を参照する。別の場所にある場合は `-Cc65Bin` で指定する。

試作 ROM は PRG-ROM 32 KiB、WRAM 8 KiB、CHR-RAM 8 KiB。起動後に FM 6声を順に鳴らし、その後は FM と APU で3つの和音を繰り返す。音源画面では 1P の左で FM 単独、右で APU 単独、下で同時発音、上で消音に切り替わる。消音から左・右・下で再開すると、最初の和音から鳴る。操作試作では消音中も射撃音が鳴る。画面に `BANK OR RAM ERROR` が出た場合は、起動時の PRG バンクまたは WRAM の検査で失敗している。

起動時の **VRC7A TEST MENU** では、**B** で元の二軸コースを開始し、**下を押しながら B** で地形と開始・復帰地点が異なる追加コースを開始する。被弾後は **START** で再挑戦し、プレイ中やクリア画面で **SELECT** を押すとメニューに戻る。リセットでも起動時のメニューに戻る。**A** の縦・斜めスクロール試験、**SELECT** の横スクロール試験、**START** の横スクロール操作試作もメニューから使える。

Mesen 2.1.1 で32 KiB版と512 KiB版の固定画面、音源の切り替え、消音中の再発音の有無、消音からの復帰、リセット後の6声の順次発音を検証した。再検証には 1P に NES コントローラーを割り当てて `Mesen.exe --testRunner --timeout=20 tools/mesen/vrc7a-smoke.lua build/vrc7a-test.nes` を実行する。512 KiB版の FM 単独・APU 単独・同時発音・消音を録音し、試作の基準値を記録した。[Mesen 測定値](docs/vrc7a-hardware-test.md#512-kib版の-mesen-測定値)

### 352402 基板向けの出力

以下の書き込み手順は、機材確保後の追加検証で使う。

`./build.ps1 -Hardware` で、同じソースから512 KiB版を生成する。Mesen には NES 2.0 ヘッダー付きの `build/vrc7a-test-512k.nes` を読み込む。ROM ライターにはヘッダーを除いた `build/vrc7a-test-512k.prg`（524,288バイト）を指定する。各8 KiBバンクの先頭に固有の識別バイトを置き、バンク3〜62の残りを `$FF` で埋める。固定バンク63はオフセット `$7E000`、割り込みとリセットのベクタは `$7FFFA–$7FFFF` に置く。[VRC7 の PRG バンク構成](https://www.nesdev.org/wiki/VRC7)

1. 使用する352402基板の U1 と、交換用 ROM・変換基板の端子対応を確認する。初回試験の候補は AT27C040-70PU と XGecu T48。端子確認後、基板から外した交換 ROM にライターで書き込む。[交換 ROM 候補と端子確認](docs/vrc7a-hardware-test.md#交換-rom-と-u1-の確認)
2. 書き込みに使った `.prg` を保存しておき、ライターでチップの先頭から524,288バイトを読み戻して別ファイルに保存する。たとえば `build/readback.bin` に保存した場合は次のコマンドで照合する。

   ```powershell
   ./tools/verify-prg-readback.ps1 -Readback build/readback.bin
   ```

   書き込み時の `.prg` を別のパスに保存した場合は `-Prg` で指定する。照合は両ファイルのサイズと全バイトを確認し、不一致なら最初に異なる位置と8 KiBバンク番号を表示して失敗する。一致したら表示された SHA-256 を試験記録に残す。
3. 同じビルドの `.nes` も保存し、ファミコンで起動、音声、通常クリアと被弾後のクリアを試す。ビルドの SHA-256 と実機・Mesen の差を記録する。[実機試験の操作と記録欄](docs/vrc7a-hardware-test.md)

起動時に `$8000` の窓で全64バンクの識別バイトを確認する。`$A000` と `$C000` の初期割り当て、`$E000` の固定バンクも確認する。32 KiB版では同じ処理で全4バンクを確認する。WRAM 検査で使用する `$6000` は、検査後に元の値へ戻す。実基板での読み戻しと動作確認は未実施。

別の Windows PC に持ち込む場合は `./tools/package-vrc7a-trial.ps1` を実行する。512 KiB版を再ビルドして `build/vrc7a-352402-trial.zip` にまとめる。展開先の `docs/vrc7a-hardware-test.md` に沿って作業する。試験用の PRG と NES イメージ、両者の `SHA256SUMS.txt`、照合・計測スクリプト、Mesen の比較画像が入っている。

- 起動時にマッパーと PPU を初期化し、仮タイルを CHR-RAM に転送する。固定画面を出し、PRG バンクと WRAM のアクセスを確認する。
- VRC7 の FM 6声を順番に鳴らした後、APU と同時に鳴らすモードを用意する。試験フレーズと効果音が重なる場面を Mesen で録音し、音量差と音割れを確認する。
- 音源ドライバは `$9010` への書き込み後に最低6 CPUサイクル、`$9030` の後に最低42 CPUサイクルを空ける。音源更新はメイン処理で行い、描画転送用の NMI から外す。
- VRC7 の FM は2オペレータで、ユーザー定義音色は6声で共有する1枠。アーケード基板の YM2203 は4オペレータ FM と SSG を持つため、VRC7 のプリセットとカスタム音色に合わせて曲を編成する。

[VRC7 音源仕様](https://www.nesdev.org/wiki/VRC7_audio) · [YM2203 データシート](https://www.bitsavers.org/components/yamaha/YM2203_198911.pdf)

## 2. スクロールと固定 HUD

音源テスト画面で 1P の **A** を押すと、縦・斜めスクロール試験に切り替わる。十字キーで768×720 pxの仮地形を移動し、SELECT で音源テスト画面に戻る。この試験では水平ミラーリングで上下2面を使い、左端8 pxを隠して画面外の列を書き換える。

縦・斜めスクロール試験から **START** を押すと、同じ地形で固定 HUD 付きの操作試作を開始する。左右で移動、A でジャンプ、B で射撃。カメラは横移動と段差・ジャンプによる高さの変化に追従する。上端32 pxには HUD 用の4行を確保する。縦追従範囲はこのコースの地形に合わせた0〜48 px。

この操作試作では、行40バイト・列27バイト・スクロール設定の後に OAM DMA を行う。FM 6声、射撃音、負荷試験用の印を同時に動かし、DMA 開始までの Mesen 計測値に最大514サイクルを加えた所要時間は1,843 CPUサイクルだった。NTSC の約2,273サイクルに対し約430サイクルの余裕がある。固定 HUD、地形の追従、スプライト、FM＋APU の更新間隔は `Mesen.exe --testRunner --timeout=40 tools/mesen/playable-two-axis-smoke.lua build/vrc7a-test.nes` で再検証できる。

新しい領域が見えるフレームの転送量は、縦移動で行と属性の40バイト、横移動で列の31バイト。同時更新の71バイトとスクロール設定は、Mesen 2.1.1 の NTSC 計測で VBlank の開始から約1,250 CPUサイクル以内に収まった。テストでは縦移動と斜め移動の往復に加え、240 px と480 pxの縦境界で地形と色が期待どおり移動することを確認した。再検証には `Mesen.exe --testRunner --timeout=45 tools/mesen/two-axis-scroll-smoke.lua build/vrc7a-test.nes` を使う。1P に NES コントローラーを設定し、フレームバッファを256×240にする。

操作試作の上端32 pxに操作案内を固定表示する。各 NMI の同じ箇所で VRC7 の IRQ を設定し、走査線31で地形のスクロール座標へ切り替える。操作試作の列転送では HUD の4タイル行を保持し、タイル52バイトと属性7バイトを更新する。Mesen 2.1.1 の NTSC 設定でネームテーブルの境界を往復し、HUD 全体の画素が同じ位置に残り、地形が1 pxずつ移動することを確認した。再検証には `Mesen.exe --testRunner --timeout=30 tools/mesen/fixed-hud-smoke.lua build/vrc7a-test.nes` を使う。[PPU の途中スクロール](https://www.nesdev.org/wiki/PPU_scrolling) · [VRC IRQ のカウンタ](https://www.nesdev.org/wiki/VRC_IRQ)

試作 ROM の音源画面で 1P の SELECT を押すと、3画面分（768 px）の仮地形に切り替わる。左右でカメラをスクロールし、SELECT で音源画面に戻る。地形画面には切り替え前に選んだ音源モードが引き継がれる。モードを操作せずに起動すると、FM の各声を鳴らした後で同時発音に移る。

横スクロールでは、メイン処理で新しい16 px幅の列を準備し、NMI でタイル60バイトと属性8バイトを VBlank 中に転送する。Mesen 2.1.1 で両端を往復し、継ぎ目の前後の画素、VBlank 内の書き込み、FM＋APU の更新間隔を確認した。再検証には `Mesen.exe --testRunner --timeout=20 tools/mesen/horizontal-scroll-smoke.lua build/vrc7a-test.nes` を使用する。1P の NES コントローラーを有効にし、左右のオーバースキャンを0に設定する。

メイン処理は VRAM の差分と OAM バッファをすべて準備してからフラグを立てる。NMI はフラグを確認して転送とスクロール設定を行い、完了後にフラグを戻す。準備に間に合わなかったフレームは、直前の画面と HUD を再表示する。Mesen でフラグの読み出しを1回だけ未準備に変え、画面が同じまま1フレーム繰り返され、その次に転送が再開することを確認した。

横スクロールと縦・斜めスクロールは、共通の16×16 pxメタタイル定義から左上・右上・左下・右下の8×8タイル番号を取得する。地形の各列は1バイトで、ビット0〜3に地表の高さを16 px単位で、ビット4〜5に横スクロール用の背景パレット番号を格納する。横スクロールでは隣り合う2列が同じパレットを使い、縦・斜めスクロールでは行位置に応じてパレットを選ぶ。操作試作の着地判定も同じ地表の高さを読む。

CHR-RAM は `$0000–$0FFF` を文字・HUD と背景に割り当て、`$1000–$1FFF` を8×16スプライトに割り当てる。いずれかのパターンテーブルが4 KiBを超えるとアセンブル時に失敗する。[現在の使用量](#512-kib-版のコース検証)

- HUD とプレイ領域の境界で VRC7 の IRQ を使ってスクロールを切り替える。IRQ は CPU サイクルを数えるため、NMI 内の決まった位置で毎フレーム設定し、境界が Mesen で安定するかを確認する。
- メイン処理で VRAM 転送リストと OAM バッファを用意し、NMI で転送する。NTSC で NMI から描画再開までは約2,273 CPUサイクル。OAM DMA の513〜514サイクルを差し引くと約1,760サイクルで、ここから割り込み処理とスクロール設定の分も確保する。

[PPU の属性とスクロール](https://www.nesdev.org/wiki/PPU_programmer_reference) · [VRC IRQ のカウンタ](https://www.nesdev.org/wiki/VRC_IRQ) · [NTSC のサイクル表](https://www.nesdev.org/wiki/Cycle_reference_chart)

## 3. 操作とスプライトの負荷試験

1P の START で操作試作を開く。左右で移動、A でジャンプ、B で射撃。敵に接触するとプレイヤーが赤くなり、START でやり直せる。SELECT で音源テスト画面に戻る。

音源画面で **A → START** と押して入る縦追従の操作試作では、コース終盤の窯型の敵が明るい色に変わり、30フレーム後に火花を左へ撃つ。火花は毎フレーム2 px進み、プレイヤーか段差に当たると枠が空く。予備動作中に B の弾を当てれば発射を止められる。既に発射された火花はそのまま進む。

Mesen では、同じ位置とタイミングからの初弾に対し、立ったままの被弾とジャンプ回避を再現した。ジャンプ回避では火花が段差で消え、同じ枠から次弾が出ることも確認した。再検証には `Mesen.exe --testRunner --timeout=50 tools/mesen/ranged-enemy-smoke.lua build/vrc7a-test.nes` を使う。

窯の手前にあるひし形の標識を越えると、被弾後の **START** で標識のすぐ右に復帰する。カメラを復帰位置に合わせ、敵と弾を初期化する。標識に着く前の被弾や、操作できる状態での **START** ではコースの最初に戻る。Mesen では到達前のやり直し、窯の再発射、連続した途中復帰を入力だけで確認した。再検証には `Mesen.exe --testRunner --timeout=50 tools/mesen/checkpoint-smoke.lua build/vrc7a-test.nes` を使う。

右端の旗の前に着地すると **COURSE CLEAR** が表示される。そこで **START** を押すと、選んだコースのチェックポイントを解除して最初から遊べる。**SELECT** でメニューに戻る。弾を飛び越える経路と被弾して途中復帰する経路は、どちらも `Mesen.exe --testRunner --timeout=50 tools/mesen/course-clear-smoke.lua build/vrc7a-test.nes` で再現できる。512 KiB版を検証する場合は ROM 名を `build/vrc7a-test-512k.nes` に置き換える。元コースのメニュー操作、再挑戦、リセットは `course-menu-smoke.lua`、バンクの切り替えと追加コースの途中復帰・クリアは `course-bank-smoke.lua` で検証できる。

同じテストで FM 6声と APU の伴奏・射撃音のレジスタ更新、HUD の画素、地形の継ぎ目を途中復帰の前後まで確認した。Mesen のスプライト制限を有効にすると、被弾直前にプレイヤー2枠、窯2枠、火花1枠と印8枠が同じ走査線に重なり、火花と3個の印が見えた。[VBlank の計測値](#512-kib-版のコース検証)

弾を出したときは本体 APU の2番目のパルスチャンネルで、6フレームかけて音程が下がる効果音を鳴らす。BGM の FM 6声と APU の1番目のパルスチャンネルを更新している間も、射撃音を最後まで鳴らす。

敵の先の低い段に、オリジナルの灯籠門と石の彫刻を配置した。プレイヤーは灯籠門の後ろを通り、隙間から見える。弾は門の手前に描く。Mesen で同じ入力を再生してプレイヤーの描画優先ビットだけを切り替え、差が門を通過するプレイヤーの画素に限られることを確認した。再検証には `Mesen.exe --testRunner --timeout=25 tools/mesen/scenery-smoke.lua build/vrc7a-test.nes` を使う。

操作試作中に十字キーの上を押すと、画面左側の同じ高さに負荷試験用の印を8個並べる。もう一度押すと解除する。Mesen のスプライト制限を有効にした状態で、プレイヤー・敵・弾の5枠と印の8枠が同じ走査線に集まる場面を確認した。プレイヤー・敵・弾の画素は負荷を掛ける前と一致し、印は3個ずつ表示された。印の順序は毎フレーム入れ替わる。再検証には `Mesen.exe --testRunner --timeout=20 tools/mesen/sprite-load-smoke.lua build/vrc7a-test.nes` を使う。

Mesen 2.1.1 で開始位置から右を押し続けた場合、敵の最初の画素が見えるのは歩行開始から25フレーム後だった。そこから57フレーム後の A、または60フレーム後の B で接触を避けて下の段まで進めた。それぞれ1フレーム遅らせると接触した。この入力条件の再検証には `Mesen.exe --testRunner --timeout=25 tools/mesen/playable-scene-smoke.lua build/vrc7a-test.nes` を使う。1P の NES コントローラーを有効にし、フレームバッファを256×240に設定する。

- Mesen で試作を操作し、敵が画面に入ってから、ジャンプと射撃それぞれが間に合う最後の入力までのフレーム数を測る。段差の手前で敵が見え、両方の対応を選べるように、コースの配置やカメラを調整する。
- プレイヤー・敵・弾が同じ高さに並ぶ場面で、どの表示が欠けると敵や弾を見失うかを確認する。この試験を先に行い、その結果を見て背景の重なり順と装飾を詰める。
- 8×16スプライトを組み合わせ、同じ走査線の8枠をプレイヤーと危険な弾に優先配分する。残りの枠はフレームごとに優先順を回し、どの場面で点滅が目立つかを記録する。
- FM 6声と APU の効果音を鳴らしながらコースを走り、描画更新が最も重いフレームを測る。負荷が高ければ、VRAM 転送量とオブジェクトの配置を調整する。

[PPU のスプライト評価](https://www.nesdev.org/wiki/PPU_sprite_evaluation)

## 移植基盤の受け入れ条件

- リポジトリのソースと試験データから32 KiB と512 KiB の診断用 `.nes` を生成できる。Mesen の NTSC 設定と1Pコントローラーで起動し、既存の音声・スクロール診断も再実行できる。
- 通常の1P入力でメニューから試験コースに入り、チェックポイント前後の再挑戦とコース終了を経てメニューへ戻れる。試験データ切り替えとリセット後に、位置・進行状態・カメラ・敵と弾が所定の初期状態に戻る。
- 横・縦スクロールの継ぎ目で背景表示と HUD の境界が安定し、行・列更新と OAM DMA が重なるフレームでも描画開始までに NMI の転送を終える。スプライト制限のある場面でプレイヤーと危険な弾を追える。
- コース中に VRC7a の FM と APU が同時に鳴り、射撃音がミックス出力に含まれる。代表例を試聴して射撃音を聞き取れることを確認する。画面切り替えや再開時の音源の状態も Mesen で確認する。
