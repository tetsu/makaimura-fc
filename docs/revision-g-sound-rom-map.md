# 国内版 Revision G の Z80 サウンド ROM マップ

対象は MAME 0.289 の `makaimurg` の `audiocpu`（Z80、3 MHz）。プログラムは `gg2.bin`（32 KiB）で、バンク切り替えなしに `$0000–$7FFF` に見える。メイン CPU 側は [6809 ROM マップ](revision-g-rom-map.md)を参照。

## メモリ配置

| CPU アドレス | 内容 |
| --- | --- |
| `$0000–$56C7` | プログラムとデータ。 |
| `$56C8–$7FFF` | `$FF` の埋め草（10,552バイト）。 |
| `$C000–$C7FF` | RAM。リセット処理が全域を0にし、スタックポインタを `$C800` に置く。 |
| `$C800` | メイン CPU からのサウンドコマンド（読み出し）。 |
| `$E000`／`$E001` | 1個目の YM2203 のアドレス／データ。 |
| `$E002`／`$E003` | 2個目の YM2203 のアドレス／データ。 |

[MAME のサウンド側メモリマップ](https://github.com/mamedev/mame/blob/mame0289/src/mame/capcom/gng.cpp)

## 起動と割り込み

| 起点 | 種別 | 確認した内容 |
| --- | --- | --- |
| `$0000` | コード | `IM 1` を設定して `$00E5` へ跳ぶ。`$00E5` は待ちループの後に RAM を消去し、両方の YM2203 のレジスタ `$2D`、`$2E` を選択してから `EI` と `JR` の待機ループ（`$010B`）に入る。 |
| `$0018`、`$0020`、`$0028` | コード | 表引き用の RST。`$18` は `HL += A`、`$20` は `A = (HL + A)`、`$28` は `A` を2倍して `DE` に語を読む。 |
| `$0030` | コード | 分岐表による跳躍。`RST $30` の直後に置いた語の表を `A` で引いて跳ぶ。呼び出し元へは戻らない。 |
| `$0038` | コード | IRQ の入口。`$00D4` でカウンタ `$C000` を進め、`$010E`（コマンド受付）、`$031A`（曲の更新）、`$0620`（効果音の進行）、`$0A68`（SSG レジスタの書き込み）を順に呼ぶ。IRQ は1フレームに4回（240 Hz）。 |
| `$003C–$00D0` | データ | 作者の署名の ASCII 文字列。NMI の入口 `$0066` はこの文字列の中にあり、コードはない。 |

処理の主体は IRQ で、主ループは待機だけを行う。

## コマンドの受付

`$010E` は `$C800` を読み、前回値 `$C001` と同じか `$FF` なら何もしない。それ以外は下位6ビットを `RST $30` に渡し、`$0120–$019F` の64語の表で分岐する。

| コマンド | 分岐先 | 処理 |
| --- | --- | --- |
| `$00`、`$09`、`$0A`、`$15`、`$16` | `$01A0` | `$C500` と `$C620` から `$20` バイト間隔で各5個の先頭バイトを0にする（効果音の停止）。 |
| `$01–$08`、`$0B–$14`、`$17`、`$19–$1B`、`$1E–$24`（29個） | `$0926–$0A3E` | 効果音。10バイトのスタブが `IX` にチャンネル領域、`HL` にデータの先頭を入れて `$0A48` へ跳ぶ。 |
| `$18`、`$1C`、`$1D`、`$25–$3F`（30個） | `$0FD5–$3CF5` | 曲。9バイトのスタブが領域の初期化を呼び、直後のヘッダーを `HL` に入れて `$02DE` へ跳ぶ。 |

**曲**の領域は `$C100`、`$C200`、`$C300`、`$C400` から各 `$20` バイト × 6チャンネル。`$031A` は `$C400`、`$C300`、`$C200`、`$C100` の順に先頭バイトを調べ、最初に0でない領域だけを更新する。初期化の入口は `$02B1`（`$C100`、26曲）、`$02BA`（`$C200`、コマンド `$30` と `$3B`）、`$02CC`（`$C400`、コマンド `$1D`、`$35`、`$37`）。`$C300` 用の `$02C3` はどこからも参照されない。

| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `$01` | `$C560` | `$3D63` | `$0D` | `$C620` | `$44DE` | `$1A` | `$C640` | `$4DDB` |
| `$02` | `$C540` | `$3E30` | `$0E` | `$C540` | `$452A` | `$1B` | `$C640` | `$4ECA` |
| `$03` | `$C660` | `$3E9A` | `$0F` | `$C660` | `$45AF` | `$1E` | `$C540` | `$4F20` |

## コマンドと場面の対応

### 6809 側の送出

| 位置 | 内容 |
| --- | --- |
| fixed:`$776D` | `B` のコマンドを `$0140–$017F` のリングバッファに積む。`$52` と `$28` が両方0のときは積まない。`$7775` はこの判定を飛ばす入口。 |
| fixed:`$7788` | IRQ（`$65DC`）から呼ばれ、バッファから1個取り出して `$3A00` に書く。 |
| fixed:`$77BB` | `B` を積んだ後に `$FF` を積む。Z80 は前回と同じ値を無視するので、同じ効果音を続けて鳴らす経路はここを通る。 |
| fixed:`$779E–$78CB` | コマンドごとのスタブ。`LDB #コマンド` の後に `$776D` か `$77BB` へ跳ぶ。 |
| fixed:`$8DE7–$8E31` | ステージ曲の選択。`bank2:$4300` のページ表（1ページ4バイト）の3バイト目を読み、現在の曲 `$BD` より大きければ `$BD` に保存して送る。 |

下の表の根拠は次の3種類。**実測**は MAME でコマンドの要求を記録し、再現スクリプトが記録した出来事や入力とフレームを照合したもの。**コード**は呼び出し元の条件を逆アセンブルで読んだもの。**推定**は実測した時点や呼び出し元の位置からの推測で、音そのものは確認していない。

### 記録の方法

`tools/mame/log-revg-sound.lua` は `$776D` がバッファに書くたびに、フレーム、コマンド、スタックの上3語、区間 `$72` を `sound_request` 行に出力する。スタックの語から呼び出し元が分かる。`$3A00` への書き込みは `sound_latch` 行に出す。環境変数 `REVG_SOUND_SCENARIO` に既存の計測スクリプトを指定すると、その入力で進めながら記録する。

```powershell
$mameDir = "$env:USERPROFILE/tools/mame/mame0289"
$env:REVG_SOUND_SCENARIO = 'tools/mame/measure-revg-stage1-end.lua'
$env:REVG_STAGE1_END = 'key'
& "$mameDir/mame.exe" makaimurg -rompath reference -noreadconfig -video none -sound none -nothrottle -skip_gameinfo -autoboot_delay 0 -autoboot_script tools/mame/log-revg-sound.lua -cfg_directory build/revg-sound-log/cfg -nvram_directory build/revg-sound-log/nvram -seconds_to_run 372
Remove-Item Env:REVG_SOUND_SCENARIO, Env:REVG_STAGE1_END
```

上の例は区間0を鍵の取得まで進める試行で、`sound_request` は486行になる。コールドブートからの2回の実行で `sound_` 行が一致した。ほかに入力計測の `shot` と `jump`、水面への落下、ボス名簿の区間0〜6、縦スクロールの鍵（区間4）、武器の試行を同じ方法で記録した。

効果音の送出元の敵は `tools/mame/log-revg-sound-sources.lua` で調べた。

- 要求が積まれた瞬間の X レジスタから、更新中の枠を判定する。敵の枠は `$0890` から `$30` 刻みで40枠、足場の枠は `$1010` から `$20` 刻みで30枠、プレイヤーの枠は `$0510` にある。
- 判定した枠の種別、バリアント、状態、座標を、コマンドと呼び出し元の組ごとに1回だけ `source` 行に出す。
- 入力は2通りある。1つは右を押し続け、64フレームごとに跳び、8フレームごとに撃つ。もう1つは `REVG_SOURCES_SEED` を指定して、16フレームごとに方向とジャンプを疑似乱数で選ぶ。
- `REVG_SOURCES_SNAP` に指定したコマンドが初めて要求されたフレームと、その20フレーム後を撮影する。

区間0〜6をそれぞれ、右進行で3,600フレームと、乱数入力で5,400フレーム（2種類の種）動かした。区間0で `$03` と `$0E` の場面を撮影した。周期（32、64、128フレーム）は、記録できた状態と区間での値。無敵にした試行では被弾・死亡・変身の経路を通らないので、記録に出ないことは、その音が鳴らない根拠にならない。`$0E` を松明の炎とした根拠は1組の撮影だけ。

```powershell
$env:REVG_SOURCES_SECTION = '0'
$env:REVG_SOURCES_SEED = '1'
$env:REVG_SOURCES_FRAMES = '1700'
$env:REVG_SOURCES_SNAP = '03'
& "$mameDir/mame.exe" makaimurg -rompath reference -noreadconfig -video none -sound none -nothrottle -skip_gameinfo -autoboot_delay 0 -autoboot_script tools/mame/log-revg-sound-sources.lua -cfg_directory build/revg-sound-sources/cfg -nvram_directory build/revg-sound-sources/nvram -snapshot_directory build/revg-sound-sources/snap
Remove-Item Env:REVG_SOURCES_SECTION, Env:REVG_SOURCES_SEED, Env:REVG_SOURCES_FRAMES, Env:REVG_SOURCES_SNAP
```

この例では、`$03` が t = 1502 と t = 1602 に種別 `$07`（枠 `$0DA0`）から要求される。`REVG_SOURCES_HITS=1` を付けると `$AD` を書き換えず、敵の攻撃が当たる。

## 曲と効果音のデータ形式

曲は FM だけ、効果音は SSG だけを使う。下の「ティック」は IRQ 1回（1/240秒）。書式はコードを読んで決め、ドライバーを Python に移したモデルの出力を MAME の YM2203 への書き込みと照合した（[照合](#データ形式の照合)）。

### 曲のヘッダー

| 位置 | 内容 |
| --- | --- |
| +0 | テンポ。音長1単位のティック数。 |
| +1+4n、+2+4n | チャンネル n（0–5）のデータの先頭（下位、上位）。n = 0–2 は YM1 の FM1–3、3–5 は YM2 の FM1–3。 |
| +3+4n | 最初の音色番号。 |
| +4+4n | 下位4ビットがゲート比 g。 |

音長はテンポ × 単位数（ティック）。キーオンからキーオフまでは音長 × (g + 1) / 16 ティックで、g = 0 は1として扱う。g = 15 は音長と同じになり、キーオフせずに次の音へ移る。

### 曲のイベント

上位3ビットの長さ符号 0–7 は単位数 0、0、2、4、8、16、32、64（表 `$0577`）に対応する。

| バイト | 内容 |
| --- | --- |
| 下位5ビットが `$01–$1E`、上位3ビットが2–7（`$41–$FE`） | 音符。下位5ビットが音程、上位3ビットが長さ。キーオンと F-Number を書く。 |
| 下位5ビットが0（`$00`、`$20`…`$E0`） | 休符。上位3ビットが長さ。キーオフは書かず、前の音のゲートで切れる。 |
| `$01–$1E` nn | 音色をこの番号にしてすぐに書き込み、nn の下位4ビットをゲート比にする。 |
| `$30` | 直後の1音を三連符にする。奇数ティックで2回数えるので、長さは約2/3になる。データ中346か所。 |
| `$21–$3E`（`$30` 以外） | 続く (値 + 1) & `$1F` 個の音符でキーオフしない。データ中1か所（`$2FAB`）。 |
| `$1F` nn | 音程表の基点を `$01EF` + 2nn に置く。音符は基点 + 2 × 音程の語を引く。 |
| `$3F` nn | テンポを nn にする。 |
| `$5F` nn | `IX+$15` に保存するが、どこからも読まない。データ中6か所。 |
| `$7F` lo hi | 跳躍。曲のループに使う。 |
| `$9F` | 繰り返しの始点。 |
| `$BF` nn | 繰り返しの終点。始点からの区間を nn + 1 回演奏する。始点は1個しか覚えないので入れ子にできない。 |
| `$DF` xx | 次のバイト xx を音符または休符として読み、単位数を1.5倍（表 `$057F`）にする。 |
| `$FF` | チャンネルの終了。キーオフは書かない。 |

**音程表** `$01EF–$02B0` は97語。項目0は0で、項目1–96はブロック0–7ごとに12個並ぶ。各語は［ブロック × 8 + F-Number 上位、F-Number 下位］で、レジスタ `$A4+ch`、`$A0+ch` にそのまま書く。MAME のクロック 1.5 MHz と、起動時に選ぶ分周比 1/3 で計算すると、項目 n は MIDI ノート番号 n（項目1は 8.65 Hz の C#-1）になる。音名はこの計算によるもので、聴いて確かめてはいない。

**音色**は `$0BD5` + 32 × 番号の32バイト。先頭24バイトをレジスタ `$30+ch` から4おきに `$8C+ch` まで（DT/MUL、TL、KS/AR、DR、SR、SL/RR の順に4オペレーターずつ）、次の1バイトを `$B0+ch`（FB/ALG）に書く。その次の1バイトがキーオンのスロットマスクで、残り6バイトは読まない。`$C010–$C015` に各 FM チャンネルへ最後に書いた音色番号を持ち、更新する層の音色と違えば毎ティック書き直す。

**層**は `$C400`、`$C300`、`$C200`、`$C100` の順に、各層の最初のチャンネルだけを見て選ぶ。下の層は進まずに止まり、上の層が終わると続きから鳴る。

### 効果音

効果音の領域は、YM1 の SSG が `$C580`、`$C560`、`$C540`、`$C520`、`$C500`、YM2 の SSG が `$C700`、`$C780`、`$C660`、`$C640`、`$C620` の優先順。`$0620` はチップごとに最初に見つかった動作中の領域だけを進め、それより下の領域は止まる。`$0A68` は毎ティック、同じ領域の値を SSG のレジスタ `$00–$0A` に11個書く。動作中の領域がなければ `$0BCA–$0BD4`（ミキサー `$FF`、ほかは0）を書く。`$C700` を使うコマンドはない。停止コマンドが消すのは `$C500–$C580` と `$C620–$C6A0` なので、`$C780` を使う `$07` は止まらない。

データはイベントの列で、最初のバイトの bit 2–4 で種類が決まる。

| bit 2–4 | 内容 |
| --- | --- |
| 0 | 待ち時間 w（上位、下位の2バイト）。続いて上位3ビットが0でないバイトを設定として読み、w ティック後に次のイベントへ進む。 |
| 1（`$04`） | 繰り返しの始点。効果音の開始時にも先頭が始点になる。 |
| 2（`$08` nn） | 繰り返しの終点。区間を nn 回演奏する。 |
| 3（`$0C` lo hi） | 跳躍。 |
| 4–7（`$10` 以上） | 終了。 |

| 設定 | 内容 |
| --- | --- |
| `$2p` qq ss | トーン A の周期 `$pqq`。0ならトーン A を切り、`$FFF` なら周期を変えずに ss だけ設定する。ss は待ちの間に毎ティック足す周期の変化量（符号付き、1/16単位）。 |
| `$4p`、`$6p` | トーン B、C の同じ設定。 |
| `$8v` ss | 音量 A を v（0–15、`$1F` は変えない）にする。ss は4ティックごとに足す変化量（1/16単位）。 |
| `$Av`、`$Cv` | 音量 B、C の同じ設定。 |
| `$Ev` mm ss | ノイズ周期を v（`$1F` は変えない）にし、mm の bit 3–5 をミキサーのノイズ許可（0で有効、A、B、C の順）に入れる。ss は4ティックごとのノイズ周期の変化量（1/8単位）。 |

ミキサーは開始時に `$FF`（全部無効）で、トーンの設定が許可ビットを変える。

### データ形式の照合

`capture-revg-sound-writes.lua` は Z80 のリセット直後から `$C800` の読み出しに1個のコマンドを返し続け、YM2203 へのデータ書き込みとティックの区切りを記録する。`decode-revg-sound.py --check` はモデルを同じコマンドで動かし、ティックごとに書き込みの列を比べる。64コマンドをそれぞれ900フレーム（3,583–3,620ティック、1コマンドあたり約8万回の書き込み）実行し、全コマンドで書き込みの値と順序が一致した。

1コマンド15秒で打ち切るので、それより長い曲の後半とループ後は照合していない。読み出したデータの全体は `decode-revg-sound.py` が `build/revg-disassembly/sound-sequences.txt` に書く。チャンネルごとに、終了かすでに通った位置への跳躍までのイベントを並べる。

## コードとデータの範囲

リセットと IRQ から分岐をたどり、`RST $30` の分岐表4個（`$011F` が64語、`$05A3`、`$0759`、`$07D6` が各8語）と、`$074D` が戻り先として積む `$0738` を入口に加えた。

| 範囲 | 内容 |
| --- | --- |
| `$0000–$003B` | リセット、RST、IRQ の入口。 |
| `$00D4–$0BC8` | ドライバ本体。途中にデータの表（`$01EF–$02B0`、`$0577–$0586`）と分岐表を含む。 |
| `$0BC9–$0FD4` | データ。 |
| `$0FD5–$3D62` | 曲。30個の9バイトのスタブと、それぞれに続くデータ。 |
| `$3D63–$56C7` | 効果音のデータ。 |

命令は1,203個、2,725バイト。データは19,315バイト、分岐表は176バイト。次の3か所は ROM 内に参照がなく、未使用のコードとして扱った。

- `$01BB–$01EE`：`$C100` からの4領域を止め、両方の YM2203 に書き込むルーチン。
- `$02C3–$02CB`：`$C300` の領域を初期化する入口。
- `$059A`：単独の `RET`。

## 実行トレースとの照合

MAME のデバッガーで Z80 の実行トレースを取り、実行された命令のアドレスをすべて上のコード範囲と比べた。`$C800` の読み出しを差し替え、Z80 が最初にコマンドを読んだフレームから30フレームごとに `$00` から `$3F` までを順に与えた。

- 範囲外のアドレスの実行は0件。
- 1,203命令のうち1,151命令を実行した。
- 実行されなかった52命令は、トレース開始前に通過した `$0000`、上記の未使用の3か所、`$0024`、`$0466`、`$0475–$047B`、`$054D`、`$05C3–$05C9`、`$05D1–$05DE`、`$0746–$074A`、`$07AB–$07B8`。

各コマンドを30フレームで打ち切るので、曲や効果音の後半だけで使うデータ列の命令は通らない。コールドブートからの2回の実行でトレースファイルの SHA-1 が一致した。

## 再現手順

```powershell
$mameDir = "$env:USERPROFILE/tools/mame/mame0289"
python tools/mame/disassemble-revg.py --unidasm "$mameDir/unidasm.exe"
python tools/mame/trace-revg-sound.py --unidasm "$mameDir/unidasm.exe"
New-Item -ItemType Directory -Force build/revg-sound-trace | Out-Null
& "$mameDir/mame.exe" makaimurg -rompath reference -noreadconfig -video none -sound none -nothrottle -skip_gameinfo -debug -debugger none -autoboot_delay 0 -autoboot_script tools/mame/measure-revg-sound-coverage.lua -cfg_directory build/revg-sound-trace/cfg -nvram_directory build/revg-sound-trace/nvram -seconds_to_run 60
python tools/mame/trace-revg-sound.py --unidasm "$mameDir/unidasm.exe" --trace build/revg-sound-trace/z80.tr
```

`disassemble-revg.py` は `gg2.bin` を MAME の SHA-1 と照合し、`build/revg-disassembly/` に `sound.bin` と、先頭から順にデコードした `sound.asm` を出力する。`trace-revg-sound.py` は到達できる命令だけをデコードし、分岐先にラベルを付けた `sound-traced.asm` を同じ場所に出力する。到達しないバイトは `db`、分岐表は `dw` で並べる。

MAME の実行はトレースを `build/revg-sound-trace/z80.tr`（約60 MB）に書き出し、最後のコマンドの後に終了する。`--trace` を付けた実行は、範囲外の実行があれば該当アドレスを表示して終了コード1を返す。

データ形式の一覧と照合は次のとおり。`--capture` は MAME をコマンドごとに64回起動し（1回約2秒）、`build/revg-sound-writes/` に書き込みの記録を残す。`--check` は不一致があれば最初のティックの両方の書き込みを表示し、終了コード1を返す。

```powershell
python tools/mame/decode-revg-sound.py
python tools/mame/decode-revg-sound.py --capture --mame $mameDir --frames 900
python tools/mame/decode-revg-sound.py --check
```
