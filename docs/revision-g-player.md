# Revision G のプレイヤーの歩きとジャンプ

FC 版の通常ゲームモード（`src/arcade-player.inc`）の歩きとジャンプは、Revision G の 6809 のプレイヤー処理（固定 ROM の `$8F0E` から）を書き写したもの。`tools/compare-player-trace.py` が MAME と Mesen に同じ入力を流し、1回の更新ごとに位置を突き合わせる。

## レコードの並び

プレイヤーのレコードは `$0500` から。処理は `X = $0510` を基準にして読む。位置と速さは、整数の上位から並ぶビッグエンディアン。

| 番地 | 内容 | FC での置き場 |
| --- | --- | --- |
| `$0503` | 主状態。1 地上、2 ジャンプ、3 被弾 | `ap_state` |
| `$0504` | 副状態。地上では 1 が端から落ちている途中。ジャンプでは 0 開始、1 上昇、2 下降 | `ap_jump_phase` |
| `$0506–$0508` | X。整数16ビットと小数8ビット | `player_x`、`ap_x_frac` |
| `$0509–$050B` | 高さ Y（上が正）。整数16ビットと小数8ビット | `player_feet`・`ap_player_y_hi`（下が正）、`ap_y_frac` |
| `$050C` | 歩く速さの表へのポインタ（`$93B6`） | 定数 |
| `$050E` | 動く方向。0 なし、1 右、2 左 | `ap_move_dir`、ジャンプ中は `ap_air_dir` |
| `$051E` | 向き | `player_left` |
| `$0516–$0519` | 横の速さ。整数16ビットと小数16ビット | `ap_vx`（整数の下位と小数） |
| `$051A–$051D` | 縦の速さ。上昇中は上向き、下降中は下向きの大きさ | `ap_vy`（同上） |
| `$0523` | 加速の表へのポインタ（`$93BA`） | 定数 |

FC の小数 `ap_y_frac` はアーケードの高さの小数のまま持つ。足元は `player_feet = 定数 − 高さの整数部` なので、高さに速さを足すときは小数の桁上がりを含めて `player_feet` から引く。

## 入力

- IRQ の `$6772` が読んだ入力を、次のプレイ更新が `$004B` に移す。前回の値は `$004C`。
- MAME で入力を書き換えると、その次の更新ではなく、さらに1回後の更新で効く。
- FC は `ap_update_frame` の頭で、1フレーム前のパッドを `ap_pad` に、その押し始めを `ap_pressed` に入れる。プレイヤー（歩き・ジャンプ・はしご・しゃがみ・射撃）はこの2つだけを読む。

## 歩き（`$8FDF`、`$9233`、`$9265`、`$92DA`）

1回の更新は、方向（`$9233`）、歩き（`$9265`）、接地（`$9034`）、ジャンプの受付（`$907B`）の順。

- 方向は `$004B & $004C`、つまり今回と前回の両方で押されているものだけを数える。左を先に調べる。
- 方向がなければ `$050E` を0にする。
- 新しい方向になった更新でも、向きを変えたうえで歩く（`$9263` の `CLRB` がキャリーを消す）。
- 歩く量は `$93B6` の表で、右が `$0120`、左が `$FEE0`。1回に 288/256 px。
- 射撃の動作中（`$052A` が0でない間）は歩かない。

## ジャンプ（`$907B`、`$93CA`、`$9415`、`$942B`、`$946A`、`$952D`）

- **受付。** `$004B & ~$004C` のジャンプが立った更新で、主状態を2、副状態を0にする。
- **開始。** 次の更新の `$9415` は、副状態を1にするだけで動かない。
- **方向。** 横の方向は受付のときの `$050E` で決まり、空中では変わらない。方向とジャンプを同じ更新で押し始めると、方向がまだ2回そろっていないので真上に跳ぶ。
- **空中の向き。** 空中では向き（`$9572`）だけが入力に従う。
- **初めの速さ。** 着地（`$953E`）と区間の開始（`$8F6B`）で `$93C2` の8バイトを速さに写す。横は 0.5 px（`$0000.8000`）、縦は 4.25 px（`$0004.4000`）。

| 副状態 | 1回の更新 |
| --- | --- |
| 1 上昇（`$942B`） | 横に動く。高さに縦の速さを足す。横の速さに `$0FA0`/65536 を足し、縦の速さから `$3D90`/65536（0.2405 px）を引く（`$94EA`）。縦の速さの整数と小数上位が `$003D` 未満になったら副状態2。 |
| 2 下降（`$946A`） | 横に動く。高さから縦の速さを引く。接地（`$8B0A`）したら着地。しなければ `$950C` で、横の速さの小数16ビットから `$0FA0` を引き、結果の最上位ビットが立たないときだけ書き戻す。縦の速さの整数が5未満なら `$3D90` を足す。 |

- **着地（`$952D`）。** 高さを地面に合わせる（小数は残る）。主状態を1に戻し、`$050E` を0にし、速さを `$93C2` に戻す。
- **再ジャンプ。** 着地した更新の次の更新では、ジャンプの押し始めがもう前回の値に入っているので、押したままでは跳ばない。
- **形。** 平地のジャンプは、受付から着地まで36回の更新で、高さは最大40 px。前跳びは約40 px 進む。

## 端から落ちる（`$9055`）

接地しなくなると、地上の副状態1に入る。横には動かず、速さは着地のときに戻した値（下向き 4.25 px）から始まり、ジャンプの下降と同じ加速で落ちる。FC は `ap_begin_fall` が副状態2の空中に入れ、方向を0にして速さを戻す。

## MAME との突き合わせ

```powershell
./build.ps1 -Hardware -RevgStage1
python tools/compare-player-trace.py
```

- **MAME 側。** `tools/mame/record-revg-player.lua` が、区間0の開始で操作できるようになった更新（通知1140）から入力を流し、更新ごとにレコードを出す。
  - 敵が出ないように、通知1000からは共有の空き敵枠 `$93` を0に保つ。
  - 開始の小数（デモの残り）は0にそろえる。
- **Mesen 側。** `build/player-trace/<試行>.lua` を生成し、`-RevgStage1` の ROM で、開始後の最初の更新から同じボタンを流す。
- **比べるもの。** 開始位置からの X と高さの差、空中かどうか。一致しなければ、最初に違った更新と前後の値を表示して終了コード1を返す。

| 試行 | 内容 | 結果 |
| --- | --- | --- |
| `walk` | 右40回、左30回、短い切り返し、1回だけ離す | 156回すべて一致 |
| `jump` | その場跳び、押し続け、着地直後の押し直し | 203回すべて一致 |
| `forward` | 右・左の前跳び、方向と同時押し（真上）、空中で逆を押す | 287回すべて一致 |
| `tombstone` | 墓石まで歩いて跳び乗る（既知の差。名前を指定したときだけ実行） | 更新143で違う |

`tombstone` の差は地形の側にある。

- アーケードの墓石は、X 256 を中心とする足場の物体で、プレイヤーは X 243 で止まる。
- FC は X 256〜271 を固いマスにしているので、X 249 まで進む。
- 墓石を BG のタイルにして、当たりを足場の枠（`$9E14` 系）に合わせるときに直す。

## まだ書き写していない部分

- しゃがみ、はしご、射撃の動作と、射撃中に歩けない時間。今は FC の試作の処理で、射撃の止まる時間は15フレーム。
- 被弾の仰け反り（`$995F`）と死亡。
- カメラ。アーケードは右へ進むとき、X − カメラ X = 128 を保って追う。FC は画面の 64〜192 の帯で追う。
- 画面端の止まり方。アーケードはカメラから10 px のところで歩きもジャンプの方向も止める。
- 墓石・移動足場の上での判定（`$9E14`）と壁の押し戻し量（`$8B7D`、`$8BAF`）。
