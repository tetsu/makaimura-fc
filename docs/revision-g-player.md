# Revision G のプレイヤーの歩き・ジャンプ・しゃがみ・はしご・射撃

FC 版の通常ゲームモード（`src/arcade-player.inc`）の歩き・ジャンプ・しゃがみ・はしご・床と墓石・カメラ・槍は、Revision G の 6809 のプレイヤー処理（固定 ROM の `$8F0E` から）を書き写したもの。`tools/compare-player-trace.py` が MAME と Mesen に同じ入力を流し、1回の更新ごとに位置を突き合わせる。

## レコードの並び

プレイヤーのレコードは `$0500` から。処理は `X = $0510` を基準にして読む。位置と速さは、整数の上位から並ぶビッグエンディアン。

| 番地 | 内容 | FC での置き場 |
| --- | --- | --- |
| `$0503` | 主状態。1 地上、2 ジャンプ、3 被弾 | `ap_state` |
| `$0504` | 副状態。地上では 1 が端から落ちている途中。ジャンプでは 0 開始、1 上昇、2 下降 | `ap_jump_phase` |
| `$0506–$0508` | X。整数16ビットと小数8ビット | `player_x`、`ap_x_frac` |
| `$0509–$050B` | 高さ Y（上が正）。整数16ビットと小数8ビット | `player_feet`・`ap_player_y_hi`（下が正）、`ap_y_frac` |
| `$050C` | 歩く速さの表へのポインタ（`$93B6`） | 定数 |
| `$050E` | 動く方向。0 なし、1 右、2 左 | `ap_move_dir`、ジャンプ中は `ap_air_dir` |
| `$051E` | 向き。1 右、2 左 | `player_left`（0 右、1 左） |
| `$051F` | しゃがみ | `ap_crouch` |
| `$0520` | しゃがみから立つまでの残り | `ap_crouch_wait` |
| `$0525` | 上下の入力。3 上、4 下、0 どちらもなし | `ap_stick` |
| `$0526` | はしごにいる | `ap_state` = `ap_state_ladder` |
| `$0527` | はしごに乗る・降りるときの数え | `ap_ladder_anim` |
| `$052C` | 支えを調べるとき、プレイヤーが上にいることを求める | `ap_tomb_above` |
| `$0516–$0519` | 横の速さ。整数16ビットと小数16ビット | `ap_vx`（整数の下位と小数） |
| `$051A–$051D` | 縦の速さ。上昇中は上向き、下降中は下向きの大きさ | `ap_vy`（同上） |
| `$0523` | 加速の表へのポインタ（`$93BA`） | 定数 |

FC の小数 `ap_y_frac` はアーケードの高さの小数のまま持つ。足元は `player_feet = 定数 − 高さの整数部` なので、高さに速さを足すときは小数の桁上がりを含めて `player_feet` から引く。

## 入力

- IRQ の `$6772` が読んだ入力を、次のプレイ更新が `$004B` に移す。前回の値は `$004C`。
- MAME で入力を書き換えると、その次の更新ではなく、さらに1回後の更新で効く。
- FC は `ap_update_frame` の頭で、1フレーム前のパッドを `ap_pad` に、その押し始めを `ap_pressed` に入れる。プレイヤー（歩き・ジャンプ・はしご・しゃがみ・射撃）はこの2つだけを読む。

## 歩き（`$8FDF`、`$9233`、`$9265`、`$92DA`）

1回の更新は、方向（`$9233`）、歩き（`$9265`）、接地（`$9034`）、ジャンプの受付（`$907B`）の順。

- 方向は `$004B & $004C`、つまり今回と前回の両方で押されているものだけを数える。左を先に調べる。
- 方向がなければ `$050E` を0にする。
- 新しい方向になった更新でも、向きを変えたうえで歩く（`$9263` の `CLRB` がキャリーを消す）。
- 歩く量は `$93B6` の表で、右が `$0120`、左が `$FEE0`。1回に 288/256 px。
- 射撃の動作中（`$052A` が0でない間）は歩かない。

## ジャンプ（`$907B`、`$93CA`、`$9415`、`$942B`、`$946A`、`$952D`）

- **受付。** `$004B & ~$004C` のジャンプが立った更新で、主状態を2、副状態を0にする。
- **開始。** 次の更新の `$9415` は、副状態を1にするだけで動かない。
- **方向。** 横の方向は受付のときの `$050E` で決まり、空中では変わらない。方向とジャンプを同じ更新で押し始めると、方向がまだ2回そろっていないので真上に跳ぶ。
- **空中の向き。** 空中では向き（`$9572`）だけが入力に従う。
- **初めの速さ。** 着地（`$953E`）と区間の開始（`$8F6B`）で `$93C2` の8バイトを速さに写す。横は 0.5 px（`$0000.8000`）、縦は 4.25 px（`$0004.4000`）。

| 副状態 | 1回の更新 |
| --- | --- |
| 1 上昇（`$942B`） | 横に動く。高さに縦の速さを足す。横の速さに `$0FA0`/65536 を足し、縦の速さから `$3D90`/65536（0.2405 px）を引く（`$94EA`）。縦の速さの整数と小数上位が `$003D` 未満になったら副状態2。 |
| 2 下降（`$946A`） | 横に動く。高さから縦の速さを引く。接地（`$8B0A`）したら着地。しなければ `$950C` で、横の速さの小数16ビットから `$0FA0` を引き、結果の最上位ビットが立たないときだけ書き戻す。縦の速さの整数が5未満なら `$3D90` を足す。 |

- **着地（`$952D`）。** 高さを地面に合わせる（小数は残る）。主状態を1に戻し、`$050E` を0にし、速さを `$93C2` に戻す。
- **再ジャンプ。** 着地した更新の次の更新では、ジャンプの押し始めがもう前回の値に入っているので、押したままでは跳ばない。
- **形。** 平地のジャンプは、受付から着地まで36回の更新で、高さは最大40 px。前跳びは約40 px 進む。

## 端から落ちる（`$9055`）

接地しなくなると、地上の副状態1に入る。横には動かず、速さは着地のときに戻した値（下向き 4.25 px）から始まり、ジャンプの下降と同じ加速で落ちる。しゃがみ（`$051F`）は消さないので、はしごの下端でしゃがんで降りると、しゃがんだまま落ちて着く。FC は `ap_begin_fall` が副状態2の空中に入れ、方向を0にして速さを戻す。本編のビルドでは、しゃがみを消さない。

## 床（`$8B0A`、`$904F`）

床のタイルは、高さの表（`$448E`）の値の分だけ足元を支える。区間0の床は14 px。

- 足元が床の面から14 px 下までにあれば、上から来たかどうかにかかわらず、床に立つ。
- 地上の更新（`$9034`）は、そのたびに足元を床の面に持ち上げる（`$904F`）。ジャンプの下降で見つけたときは着地（`$952D`）で合わせる。
- はしごの一番上のタイルは、床でもある。はしごを上りきると、足元は床の面より下にあり、地上の更新で持ち上がる。

FC（本編のビルド）は、一方通行の床とはしごの上端で、足元がマスの上端から14 px 以内なら支える（`ap_probe_foot`）。地上の更新は `ap_revg_ground` で足元をマスの上端にそろえる。試作の7面は、今までどおり上から通り過ぎたときだけ止まる。

## 墓石（`$9E14`）

墓石は BG のタイルではなく、支えの物体（`$1010 + $20 × n`、種類1）。中心の X と高さ（立つ床と同じ高さ。区間0の地面では62）を持ち、枠は `$9EB8` の表で、X が中心 ±12、高さが中心 ±19。

| 使うところ | 調べる点 | 当たったとき |
| --- | --- | --- |
| 歩き（`$9271`、`$9298`） | X ± 1、高さ + 1 | 歩かない。右へは X 243 で止まる（墓石 X 256） |
| 地上の支え（`$9034`）、下降（`$949B`） | X、高さ − 1。プレイヤーが中心より下なら当たらない（`$052C`） | 墓石の上に立つ。下降なら着地（`$9532`） |

- 当たったとき、プレイヤーの高さが中心から3 px を超えて離れていれば、高さを中心 + 19（墓石の上）にする。そのため、墓石の横に落ちてきても上に乗る。
- 上昇中と空中の横の動きでは調べない。前跳びは墓石の上を通り抜けられる。
- `$052C` は支えを調べるときに1にし、どの物体にも当たらなければ0に戻す。

FC（本編のビルド）は、変換した表 `revg_tomb_x_lo`・`revg_tomb_x_hi`・`revg_tomb_feet`（`tools/convert-revg-section.py`）を `ap_tomb_box` で調べる。歩きの頭で `ap_tomb_probe_ahead`、床が見つからなかったときに `ap_tomb_support` を呼ぶ。マップの墓石のマス（`mt_tomb`）は絵だけで、当たりはない。

## はしご（`$908B`、`$9174`、`$91AD`、`$91CF`、`$90D2`、`$9101`）

はしごはタイル（番号 `$40–$7D`）。はしごにいる間も主状態は地上のままで、`$0526` が1になる。上下の入力（`$908B`）がはしごを扱う。

- **上で乗る（`$9174`）。** プレイヤーの高さのタイルがはしごなら、X をはしごの中心線（2列のはしごの境目）に合わせ、`$0525` が3でなければ乗る。構えと動く方向を0にする。乗った更新は動かない。
- **下で乗る（`$91AD`）。** 18 px 下のタイルがはしごで、はしごにいなければ、14 px 下げて乗る。そこから17回の更新はその場で、18回目から下りる（`$9101`）。
- **上り下り（`$91CF`）。** 上なら1回に 1.375 px（`$0160`）上り、下なら同じだけ下りる。
- **上で降りる（`$90D2`）。** 上を押していて、プレイヤーの高さのタイルがはしごでなくなると、17回の更新はその場で、18回目にはしごを離れる。床の中にいるので、地上の更新で床に持ち上がる。
- **下で降りる（`$9157`）。** 18 px 下のタイルがはしごでなくなると、すぐ離れる。`$0525` が4でなければ（上で乗ったか、途中で離した）、しゃがむ。地面より少し上なので、しゃがんだまま落ちる。
- **何も押さない。** その場で止まる。
- **はしごの上では撃てない。** はしごの更新は射撃の構え（`$8F71`）を呼ばない。

はしごの途中の数え `$0527` は、下で乗るときと上で降りるときで共有する。

FC（本編のビルド）は、`ap_state_ladder` を `$0526` として、はしごでも `ap_step_ground_revg` を走らせる。`ap_revg_stick` が `$908B`、`ap_ladder_at` が `$9174`・`$91AD`、`ap_ladder_move` が `$91CF`。

- 変換したマップは、はしごのマスをアーケードのタイルより1行上に置いている。そのため、アーケードの高さ Y のタイルは、FC の行 `(足元 + 1) / 16 − 1` を見る。
- 中心線は、右隣の列もはしごなら右端、そうでなければ左端。区間0のはしごはすべて2列。
- X が中心線に合うとき、アーケードのカメラは一度に動くが、FC は1フレームに 4 px までしか動かないので、数フレーム遅れて追いつく。

## しゃがみ（`$908B`、`$9017`、`$98AB`）

### 上下の入力（`$908B`）

立っていても、しゃがんでいても、更新の初めに上下を見る。方向と同じく、今回と前回の両方で押されているものだけを数え、上を先に調べる。

- **上。** はしごがなければ、`$0525` が3でないときだけ、3にしてしゃがみを解く。しゃがんでいてもすぐ立つ。
- **下。** はしごがなければ、`$0525` が4でないときだけ、4にしてしゃがむ。
- **どちらもなし。** `$0525` を0にする。

### 立っている更新（`$8FDF`）

上下、射撃の構え、方向、歩き、接地、ジャンプの受付の順。しゃがみに入った更新も、そのまま歩き、跳べる。

### しゃがんでいる更新（`$9017`）

- 動く方向 `$050E` を0にする。歩かない。
- 上下を見る。下を押している間は、そのまましゃがむ。
- 上下どちらも押していなければ、立つ処理（`$98AB`）に進む。
- ジャンプの受付、射撃の構え、接地の順に続く。動く方向が0なので、しゃがみからのジャンプは真上に跳ぶ。

### 立つ（`$98AB`）

- **方向を押している。** 向いていない方向なら、しゃがんだまま向きを変える。向いている方向なら、構えの間は待ち、構えがなければ `$0520` を数える。
  - `$0520` が0ならすぐ立つ。0でなければ1減らし、0になったら立つ。
  - 立つときは `$0520` を7にする。区間の開始では10（`$8F52`）。
- **方向を押していない。** 構えの間は待つ。構えがなければ、`$0505` を段階に使う。
  - 段階0なら `$0520` を15にして段階1にする。
  - 段階1では `$0520` を1減らし、0になったら立って段階0に戻す。
  - そのため、下を離してから15回目の更新で立つ。
  - `$0505` は射撃の構えと同じ番地なので、FC も `ap_shot_phase` を共有する。

### ジャンプ中のしゃがみ（`$93CA`、`$93FF`）

- 方向のあるジャンプは、毎回の更新の頭でしゃがみと `$0525` を0にする。
- 真上のジャンプでは消さない。しゃがみから真上に跳ぶと、空中でもしゃがみのまま（槍も低い位置から出る）。
- `$907B` のジャンプの受付は、`$0505` も0にする。

FC（本編のビルド）は、`ap_step_ground_revg`、`ap_revg_stick`、`ap_crouch_release`、`ap_revg_jump_check` に書き写した。はしごは下の「はしご」の節。試作の7面（`-Prototype`）は、今までどおり下を押している間だけしゃがむ。

## カメラ（`$8001`、`$8291`）と画面端（`$9283`、`$92A9`、`$93CA`）

アーケードのカメラ X は `word($9C)`。プレイの更新ごとに、プレイヤーの X との差（整数部）を見る。

- **差が129以上。** カメラ X が右の上限 `$5A` 未満なら、カメラを X − 128 にする（小数もプレイヤーの値になる）。上限は動かす前に比べるので、1回だけ上限を少し越えることがある（区間0では3328に対して3329）。
- **差が128未満。** カメラ X が左の下限 `$58` より大きければ、カメラを X − 128 にする。0より左には行かない。
- **差が128ちょうど。** 動かない。
- 小数はプレイヤーと同じになるので、整数部はいつも X − 128 になる。FC は小数を持たず、整数部だけを合わせる。

FC（本編のビルドの `ap_follow_camera`）は、差に合わせて1フレームに最大4 px 動かす。1 px を超える分は `pan_directions` の bit 6〜4 に入れ、本編のビルドだけにある `prepare_pan_steps` が1 px ずつ動かす。ほかのビルドの `prepare_pan` は変えていない（数サイクル増やしただけで、横スクロールのコースの試験の敵の出現位置がずれた）。8 px 未満なので、新しい列は1フレームに1つまで。右の上限は、FC ではページ単位の `stage_cam_x_max_hi` で止まるので、越えない。

画面端では、プレイヤーは X − カメラ X が10〜246の間だけで動く。

- **歩き。** 動く前に、右なら カメラ X + 256 − X、左なら X − カメラ X を見て、10未満なら、その更新では歩かない（`ap_edge_room`）。
- **ジャンプ。** どの段階でも、更新の頭で同じ値が10以下になると、空中の方向を0にする。そこから先は真上に跳んだのと同じ動きになる。
- 試作の7面（`-Prototype`）は、今までどおり画面の 64〜192 の帯で追い、左端はワールドの X 9 で止まる。

## 射撃（`$8F71`、`$9DB7`、`$9ACE`、`$9B3A`）

射撃の構えはプレイヤーの更新の中で数え、弾は自弾の枠の更新（`$9ACE`）で動かす。

### 構え（`$8F71`）

- 地上（方向の前）、しゃがみ（ジャンプの受付の後）、ジャンプの上昇と下降（向きの後）で呼ぶ。
- 構えの残り `$052A` が5以下で射撃ボタンを押し始めると、弾を投げる（`$9DB7`）。
- 押したときは、投げられたかどうかにかかわらず、`$0505` を0にする。
- `$052A` が0でなく、`$0505` が0なら、`$052A` を15にして `$0505` を1にする。
  - そのため、枠がすべて使われているときに押すと、弾は出ないまま構えだけがやり直しになる。
- そのあと `$052A` を1減らし、0になったら `$0505` を0にする。
- 構えは、押した次の更新から15回の更新で、そのうち14回は歩かない（`$9265`）。

| 構えが終わるとき | 番地 |
| --- | --- |
| 地上で新しい方向を押す（向きが変わる） | `$9259` |
| ジャンプが始まる（押した次の更新） | `$9425` |
| ジャンプから着地する | `$9544` |

空中で向きを変えても、構えは終わらない。

### 弾を投げる（`$9DB7`）

- **枠。** 自弾の枠 `$0530 + $40 × n` のうち、武器ごとの数（`$9E0F`：松明2、槍3、斧2、十字架3、短剣3）の先頭から空きを探す。
- **位置。** 右向きなら X + 15、左向きなら X のまま。高さは、立っていれば Y + 9、しゃがんでいれば Y − 3（`$9DF7`）。
- **小数。** X の小数は書き換えない。同じ枠を使い直すと、前の弾の小数が残る。

### 槍（`$9C97`、`$9B3A`）

- 投げた次の更新は、設定だけで動かない（`$9C9F`）。
- 次の更新からは、1回に 4 3/16 px（`$9C73` の `$0430`）進む。
- 投げた位置から192 px（`$9C51` の `$C0`）離れたら、状態2（`$9BEB`）と状態3（`$9CF1`）を1回ずつ経て、枠が空く。
- 画面の外に出ても、地面に当たっても消えない。止めるのは、敵と墓石だけ。

FC（本編のビルド）は、`ap_shot_pose`、`ap_throw_shot`、`ap_step_lance` に書き写した。

- `ap_shoot_lock` が `$052A`、`ap_shot_phase` が `$0505`。
- 自弾の位置は、アーケードと同じく中心で持つ。
- `ps_y` は、アーケードで弾が Y の上にある分だけ、`player_feet` の上に置く。
- 描くときは、8×16 の1枚を X の中心に置き、`ps_y` の16 px 上を真ん中にする（アーケードの Y は32 px のアーサーの真ん中なので）。
- 槍の絵は、まだ試作の1枚。

試作の7面（`-Prototype`）は、今までどおり構え15フレーム、槍2本、画面の外で消える。

## MAME との突き合わせ

```powershell
./build.ps1 -Hardware
python tools/compare-player-trace.py
```

- **MAME 側。** `tools/mame/record-revg-player.lua` が、区間0の開始で操作できるようになった更新（通知1140）から入力を流し、更新ごとにレコードを出す。
  - 敵が出ないように、通知1000からは共有の空き敵枠 `$93` を0に保つ。
  - 開始の小数（デモの残り）は0にそろえる。
- **Mesen 側。** `build/player-trace/<試行>.lua` を生成し、本編の ROM（`build/vrc7a-test-512k.nes`）で、開始後の最初の更新から同じボタンを流す。
  - タイトルでは **Right+START** を押し、開始の演出と地図を飛ばす。
  - 仮のゾンビが出ないように、毎フレーム `sched_zombies_live`（`$6077`）を上限の2に保つ。
- **比べるもの。** 次のものを比べる。一致しなければ、最初に違った更新と前後の値を表示して終了コード1を返す。
  - 開始位置からの X、高さ、カメラ X の差。
  - 空中かどうか。
