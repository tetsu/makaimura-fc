# 国内版 Revision G のステージデータ

対象は MAME 0.289 の `makaimurg`。6809 側の ROM から、全7区間の背景マップ、地形判定、ページ表、敵の出現、固定配置を読み出す方法をまとめる。アドレスの書き方は [6809 ROM マップ](revision-g-rom-map.md)と同じで、切り替え窓の参照には `bank2:$4000` のようにバンクを付ける。

[抽出ツール](../tools/mame/extract-revg-stages.py)は下記の表を ROM から直接読み、Git 管理外の `build/revg-stages/` に JSON と確認用の PNG を書く。[照合ツール](../tools/mame/verify-revg-stages.py)は、全区間の全ページから MAME でプレイを始め、背景 RAM・パレット・オブジェクト枠を抽出結果と比べる。

## 座標とページ

ワールド座標は X が右、Y が上に増える。1ページは 256×256 px。ページ番号は `行 × 32 + 列` で、行0がいちばん下になる。プレイヤー座標とページの関係は [開始・復帰座標とカメラ](revision-g-rom-map.md#開始復帰座標とカメラ)のとおり。

MAME の画面写真と ROM から描いた背景を画素単位で比べた結果、表示範囲は次のとおりだった。カメラ座標は `word($9C)`（X）と `word($9E)`（Y）。

| 軸 | 画面上の位置 | 見えるワールド範囲 |
| --- | --- | --- |
| X | 画面 x = X − カメラ X | カメラ X 〜 カメラ X + 255 |
| Y | 画面 y = カメラ Y + 239 − Y | カメラ Y + 16 〜 カメラ Y + 239（224ライン） |

背景のスクロールレジスタ `$3B08–$3B09` にはカメラ X を512で割った余り、`$3B0A–$3B0B` にはカメラ Y の符号を反転し512で割った余りが書かれる。区間0のページ3から開始した時点の写真では、画面全体の画素の91%が描画結果と一致した。一致しなかった画素はスプライトの部分。

## 背景マップ

背景は4段の表でできている。

| 段 | 位置 | 内容 |
| --- | --- | --- |
| 画面 ID の格子 | bank2:`$4000–$415F` | 32列×11行。1バイトが1ページの画面 ID。行0がいちばん下。`$4160–$41FF` は0。 |
| ブロック表の選択 | bank2:`$4200 + 2 × 画面 ID` | 画面ごとに、bank1 のブロック表の先頭を16ビットで指す。使われている表は `$4000`、`$4800`、`$5000`、`$5800` の4つ。 |
| ブロック配置 | bank0:`$4000 + 64 × 画面 ID` | 8列×8段の 32×32 px ブロック番号。列ごとに8バイトで、各列は下の段から上の段へ並ぶ。 |
| ブロック | bank1:ブロック表 + 8 × ブロック番号 | 先頭4バイトがタイル番号、後半4バイトが属性。どちらも左下・左上・右下・右上の順。 |

16 px タイルの属性は、MAME の `gng` と同じ割り当てで読むと写真と一致した。

| ビット | 意味 |
| --- | --- |
| 7–6 | タイル番号の上位2ビット（番号は10ビット） |
| 5 | 上下反転 |
| 4 | 左右反転 |
| 3 | スプライトより手前に描く |
| 2–0 | パレット番号（背景色 `$00–$3F` の8色ずつ） |

格子が参照する画面 ID は104種類（`$00–$67`）。`$67` は空の画面で、区間の外側を埋めている。

### 背景 RAM への展開

背景 RAM は 512×512 px のリングで、タイル番号が `$2800`、属性が `$2C00` にある。アドレスは列優先で、`32 × ((X >> 4) & 31) + 16 × ((Y >> 8) & 1) + 15 − ((Y >> 4) & 15)`。区間の開始と途中復帰では、`$62AB` が次の順に展開する。

1. 開始ページ p の全体（`$6309`）
2. p − 1 の全体（`$6309`）
3. p + 1 のブロック列0〜3（タイル列0〜7）。リングの同じ位置にある p − 1 の左半分を上書きする

3 の処理（`$62DC–$62E0`）は `ASLB` の後に `LDX B,X` でブロック表の先頭を引く。B のオフセットは符号付き8ビットなので、画面 ID が `$40` 以上だと `$4100 + 2 × 画面 ID` を読む。そこは格子の後ろの0の領域なので、ブロック表の先頭が `$0000` になり、ブロックを RAM から読んでしまう。右隣が区間2以降の画面（ID `$40` 以上）か、空の画面 `$67` のときにこの状態になる。画面に入る前に、列ストリーム（`$80F1`、`$8366`、`$8666`、`$8839`。どれも16ビットで引く）が正しい内容で上書きする。

区間の途中のページから開始した直後は、展開済みの右端の列が、画面左端と同じリングの列を使うことがある。開始表の座標でページ1〜4から始めた直後の MAME の写真では、画面左端の16 px に512 px 先の列が表示されていた。ゲーム自身が使う開始・途中復帰の位置では、このずれは起きなかった（下の照合結果）。

## 地形判定

判定は背景 RAM のタイル番号（下位8ビット）だけを見る。属性の bit 7–6 が0でないタイルは、どの判定でも対象外になる。

| 判定 | 表 | 使い方 |
| --- | --- | --- |
| 接地 | bank4:`$448E + 符号付きタイル番号` | 足元の高さの上限。0なら判定なし。[接地 `$8B0A`](revision-g-rom-map.md#判定点から背景-ram-と境界表を引く) |
| 右壁 | bank4:`$458E + 符号付きタイル番号` | タイル内 X が値以上なら接触。 |
| 左壁 | bank4:`$468E + 符号付きタイル番号` | タイル内 X が値以下なら接触。 |
| はしご | コード `$9174` | タイル番号が `$40–$7D` ならはしご。番号 − `$40` が奇数ならタイルの左端、偶数なら右端に X をそろえる（2タイル幅のはしごの中心線）。 |

3つの表はそれぞれ256バイトで、`$440E–$470D` に連続して並ぶ。

## ページ表

bank2:`$4300 + 4 × ページ番号`（`$4300–$487F`）。区間の開始時（向き0）と、ページ切り替え時（右 `$01`、左 `$FF`、上 `$20`、下 `$E0`）に `$8DE7` が読む。

| バイト | 内容 |
| --- | --- |
| 0 | 読み込まれるが、使う前に上書きされる。全ページで0。 |
| 1 | パレット番号を `$DE` に置く。0は変更なし。IRQ の `$6656` が bank3:`$4000 + 128 × (番号 − 1)` の128バイトを `$1632` に写し、`$6619` が背景パレット `$3800–$383F`（赤・緑）と `$3900–$393F`（青）へ送る。使われている番号は1〜14。 |
| 2 | ステージ曲のコマンド。現在の曲 `$BD` より大きいときだけ送る。ページ番号が減る向き（左 `$FF`、下 `$E0`）の切り替えでは送らない。bit 7 が立っていれば、向き0の呼び出し（区間開始時の `$6B0F`、`$6C8D`、`$70CE`）だけで送る（ページ `$00D` のみ）。[曲の一覧](revision-g-sound-rom-map.md#コマンドと場面の対応) |
| 3 | 敵グループ番号。`$0670` に置き、出現スケジューラが読む。 |

## 固定配置

どちらの表も先頭1バイトが件数で、その後に6バイトのレコードが続く。レコードは種別、バリアント、X（16ビット）、Y（16ビット）。

| 表 | 読み込み | 置き先 |
| --- | --- | --- |
| 敵（bank2:`$4B00 + 4 × 区間` が指す表） | `$6E43–$6E75` | `$8C5F` で敵の空き枠（`$0890` から `$30` 間隔の40枠）を取り、種別を `+$05`、バリアントを `−$0E`、X を `−$0A`、Y を `−$07` に書く。種別は敵の更新表と同じ番号。 |
| 足場・墓石など（bank2:`$4B02 + 4 × 区間` が指す表） | `$6E76–$6EA9` | `$8C78` で足場用の枠（`$1010` から `$20` 間隔の30枠）を取り、同じ位置に書く。 |

## 敵の出現

ページ表のグループ番号から、次の順に引く。

1. **グループ**：bank2:`$4FE0 + 2 × グループ番号` が指すデータ（107グループ、うち58に中身あり）。先頭1バイトが件数、その後に1件2バイトが続く。`$E8F0` は各バイトを上位・下位4ビットに分け、1バイト目の上位を種別、2バイト目の上位をフラグとして読む。パターン番号は1バイト目の下位 × 16 + 2バイト目の下位。種別ごとのスケジューラ `$0690 + 32 × 種別` に登録する。1グループの件数は最大3。
2. **パターン**：bank2:`$5188 + 2 × 種別` が種別ごとのポインタ表を指し、その表から `2 × パターン番号` の位置で引く（`$E9DD`）。パターンは先頭1バイトが件数で、その後のレコードを1件ずつ出現させる。登録されたパターンは82個で、グループから参照されるのは56個。
3. **レコード**：通常の種別（`$EA8B`）は6バイトで、X（16ビット）、Y（16ビット）、バリアント、次のレコードまでの待機値。フラグの bit 0 が0なら座標にカメラ X・Y を足し、1ならそのままワールド座標として使う。種別 `$0B` は `$EBF1` が X をカメラ X + 128 から向きに応じて加減し、Y は `word($A2)` を使う（2バイト目の後の2バイトは読み飛ばす）。種別 `$07`（`$EBCB`）はスケジューラ自身の座標に1体出してレコードを読まない。種別 `$0E`・`$0F`（`$EA7D`）は何も出さない。

フラグの bit 1 は一度だけ出す敵を表す。種別 `$05`、`$06`、`$08`、`$0A`、`$0C`、`$0D` で、`$EA50` がグループ番号 − `$EA84` の区間の値をビット位置にして、出現済みの印を付ける。`$B5` が0でないときは、`$E9B3` の表で1になっている種別（`$00–$04`、`$07`、`$09`、`$0B`、`$0E`、`$0F`）の新規登録を止める。出現前には、`$E9FB` が共有の空き枠 `$93` と種別ごとの残り枠 `$30 + 種別` を確認する（[開始地点の出現間隔と同時枠](revision-g-rom-map.md#開始地点の出現間隔と同時枠)）。

敵の種別ごとの更新処理は bank4:`$4712` の表にある（`$9F11` のループが40枠を回す）。`$10–$12` はグループからは出ず、区間開始時の表にだけ現れる。

| `$04` | `$E2F0` | 移動足場 | 区間1の建物の水路にあるれんがの足場（[墓石と移動足場の初期化](revision-g-rom-map.md#墓石と移動足場の初期化)）。 |
| `$05` | `$E453` | 球を並べた足場 | 灰色の球を2段に並べた足場。`$02` の経路移動に加え、プレイヤーとの距離で動作を変える。区間3はバリアント0〜3、区間4は4〜6。 |

### 足場 `$00` の中身

`$E33F` がバリアントで分岐する。

| バリアント | 見た目 | 触れたときの動作 |
| --- | --- | --- |
| 0 | 見えない | `$AC` が0でなければ、アイテム枠 `$1612` に種類0（鎧）を、X + 100、同じ Y に出す。`$AC` は被弾処理の `$99FF` が1にし、鎧の取得 `$E6EE` が0に戻す。そのため、鎧を失っているときだけ出る隠し鎧になる。鎧を着ていても仕掛けは使い切る。 |
| 1 | 見えない | 同じ枠に種類 `$13`（10,000点）を、X + 100、Y + 128 に出す。`$AC` は見ない。 |
| 2 | 浮いた円盤 | 音 `$1D` を鳴らし、絵を `$E864`（「200」）に替えて、`$6909` に `$0C04` を積む。積んだ命令は bank3:`$542F` の加点処理で、`$5492` の4番を引いて200点を足す。最後に `$E3AB–$E3BF` が `$74–$77` のビットを1つ消す。ビットの位置は足場の更新ループの残り枠数 `$E0`（30〜1）で決まり、配置の番号ではない。 |
| 3 | 浮いた円盤 | 2と同じ。絵は `$E870`（「500」）、積む命令は `$0C07` で、500点。 |

区間0では、鎧の仕掛け（バリアント0）が (1440, 96) と (2416, 112)、10,000点の仕掛け（バリアント1）が (2968, 112) にある。撮影ではバリアント1の枠を持ち上げても画面は変わらなかった。

#### 足場 `$00` の計測

`tools/mame/measure-revg-hidden-item.lua` で (1440, 96) の鎧の仕掛けを確かめた。区間0をページ `$005` から始め、プレイ開始30フレーム後に `$AC` を設定する。プレイヤーの X・Y（`$0506`・`$0509`）を8フレームの間、仕掛けの座標に置き、枠の状態とアイテム枠、音の要求を毎フレーム記録した。アイテムが拾える状態になってから30フレーム後には、プレイヤーをアイテムの位置に移した。

| 条件 | 結果 |
| --- | --- |
| `$AC = 1`（鎧なし） | 2フレーム後（t = 32）に仕掛けの状態が `$0102` から `$0200` になり、絵が `$A4AB` に替わった。同じフレームに `$1612` に種類0、状態 `$0101`、(1540, 96) のアイテムが出た。アイテムは落下し、t = 76 に Y 62 で状態 `$0103`（拾える状態）になった。t = 107 にプレイヤーが触れると `$AC` が0になり、音 `$10` が要求された。アイテムは `$0200`、`$0300` を経て、t = 138 に枠を返した。 |
| `$AC = 0`（鎧あり） | 仕掛けは同じく `$0200` → `$0201` → `$0300` と進み、t = 63 に枠を返した。アイテム枠は空のままだった。 |
| `$AC = 0` で触れた後に `$AC = 1` | t = 60 に `$AC` を1にして再び仕掛けの座標に置いたが、仕掛けの枠はすでに返されていて、アイテムは出なかった。 |

同じ方法で、(2968, 112) の10,000点の仕掛け（バリアント1）をページ `$00B` から確かめた。スコア `$68–$6B` も記録した。

| 条件 | 結果 |
| --- | --- |
| `$AC = 0` | t = 32 に仕掛けが `$0200` になり、同じフレームに `$1612` に種類 `$13`、状態 `$0101`、(3068, 240) のアイテムが出た。X + 100、Y + 128 の位置。アイテムは落下し、t = 104 に Y 62 で接地、t = 114 に拾える状態 `$0103` になった。t = 145 にプレイヤーが触れると、スコアが0から10,000になり、音 `$1D` が要求された。アイテムは t = 176 に枠を返した。 |
| `$AC = 1` | `$AC = 0` と同じフレームで、同じ結果になった。バリアント1は鎧の有無を見ない。 |

円盤は、区間0の (368, 56) の200点（バリアント2、ページ `$001`）と (1408, 56) の500点（バリアント3、ページ `$005`）で確かめた。

| 対象 | 結果 |
| --- | --- |
| 200点 | 触れた t = 32 に、スコアが0から200になり、絵が `$E864` に替わった。音 `$1D` は t = 33 に要求された。枠は t = 63 に返された。 |
| 500点 | t = 32 に、スコアが0から500になり、絵が `$E870` に替わった。同じフレームに音 `$1D` が要求された。枠は t = 63 に返された。 |

`$74–$77` への書き込みを電源投入から記録した。値を書いたのは、起動時の RAM 消去（`$6088`）と RAM 検査（`$5546`）のほかは、円盤の `$E3C1` だけだった。200点では `$E0 = 3` で `$74`、500点では `$E0 = $10` で `$76` に書いた。どちらもビットはもともと0で、値は0のまま変わらなかった。プレイ中にこのビットを1にする処理は見つからず、円盤自身もこのビットを読まない。

`tools/mame/measure-revg-disc-bits.lua` で、区間0〜6をそれぞれ通常の開始から3,000フレーム歩かせた（右を押し続け、64フレームごとにジャンプ）。電源投入から `$74–$77` を読み書きした命令を、番地ごとに記録した。

| 命令 | 内容 | 区間 |
| --- | --- | --- |
| `$6088` | 起動時に `$0000–$1FFF` を0で埋める | 全区間 |
| bank0:`$5546`・`$554F` | 起動時の RAM 検査。`$FF`、`$EE` … `$00` と書いて読み返す | 全区間 |
| `$6C2C–$6C2E` | ゲーム開始時の初期化 `$6C05` の最後で、`$0060–$008F` の48バイトを `$0440` に写す | 全区間 |
| `$E3BF`・`$E3C1` | 円盤の取得でビットを1つ消す | 円盤に触れた区間0・2・5 |

`$0060–$008F` はプレイヤーごとの状態（区間 `$72`、武器 `$73`、落とし物の選択 `$78–$7D` など）で、`$7652` は2人プレイの交代時にこの48バイトを `$0440` と入れ替える。`$74–$77` もこの中にあるので、プレイヤーごとの値として保存される。

どの区間でも、終了時の `$74–$77` は0だった。逆アセンブルでも、`$0074` を基点にする命令は `$E3BA` だけだった。`<$74`〜`<$77` を参照するように見える行は他にもあるが、どれも実行時の記録には現れなかった。そのため、このROMでは `$74–$77` は常に0のままで、円盤の消去は効果を持たない。ビットを立てる処理が削られた名残と考えられるが、他の版との比較はしていない。2人プレイの交代、ミス後の再開、ボス戦の経路は今回の記録に含まれていない。

再現は `REVG_ARMOUR_AC=0` または `1` を付け、`-autoboot_script tools/mame/measure-revg-hidden-item.lua` で MAME を起動する。10,000点の仕掛けは `REVG_HIDDEN_VARIANT=1`、200点と500点の円盤は `2` と `3` を加える。鎧の再接触の試行は `REVG_ARMOUR_RETRY=1` を加える。写真は `-snapshot_directory` に保存される。

カメラを戻したときに仕掛けが置き直されるかは調べていない。どちらのアイテムも X + 100 で画面の右外に出るため、写真では絵を確かめられなかった。

出たアイテムは枠 `$15E2`（2枠、間隔 `$30`）で落下し、接地すると取得判定 `$E6AB` に入る。取得時は bank4:`$5C20` の表を種類（`- $0E`）で引く。敵を倒したときの落とし物も同じ枠と種類を使う（`$EB0A`、6回に1回）。

| 種類 | 処理 | 内容 |
| --- | --- | --- |
| `$00` | `$E6E6` | 鎧。音 `$10`、`$AC` を0にし、プレイヤーを着替えさせる（`$9899`）。 |
| `$01–$05` | `$E6FA` | 武器。`$73` に種類 − 1 を書き、命令 `$0800` を積む。`$73 = 3`（種類4）が区間5の通常の鍵経路に通る武器（[区間5の武器と進路](revision-g-rom-map.md#区間5の武器と進路)）。 |
| `$06–$0B` | `$E70A` | 落とし物の得点アイテム（6 + 区間番号）。区間0は200点、他の区間は400点。 |
| `$0C` | `$E70A` | 落とし物の得点アイテム。10,000点。 |
| `$0D–$13` | `$E731` | 得点アイテム。順に200、500、800、1,000、2,000、5,000、10,000点。 |

加点の表 `$5492` の番号と点数は、1:10、2:50、3:100、4:200、5:300、6:400、7:500、8:800、9:1,000、10:2,000 … 18:10,000、22:100,000。各アイテムの絵柄の名前（金袋など）は確かめていない。

## MAME での照合

照合ツールは区間ごとに、通常の開始、途中復帰（区間選択時に `$81` を1にする）、カメラ範囲内の全ページ（区間0〜6で計136ページ）からの開始で MAME を起動する。全ページの試行では開始表 `$6CEE` の読み出しだけを差し替え、ページ内の X・Y は ROM の値を使う。各起動で次を確かめた。

| 対象 | 方法 | 判定 |
| --- | --- | --- |
| 初期展開 | `$633F–$6378` から背景 RAM への書き込みだけを記録し、ページ p、p − 1、p + 1 の8列と比べた。書き込みが3つのページ以外の位置にないことも確かめた。p + 1 が RAM を読む場合とページ0の p − 1 は、値を予測できないので件数だけ数える。 | 全試行 |
| 表示範囲 | プレイ状態（`$05/$08/$0B/$0E` = 1/1/1/0）になってから3フレーム後に、上の表示範囲に入るタイルを比べた。通常の開始と途中復帰では、その後120フレーム静止してから右を900フレーム押し続け、もう一度比べた（無敵時間 `$AD` を保つ。途中でプレイ状態が変わった場合は比べない）。静止中に変化したセルは比べず数だけ記録し、左端の2列は512 px 先の列と一致した場合も可とした。 | 通常の開始と途中復帰。その他のページは参考 |
| パレット | `$1632` の写しを、開始ページの番号の組と比べた。静止中の120フレームで変化した色は循環している色として記録した。 | 参考 |
| 固定配置 | 区間開始時に置く敵と足場の各レコードについて、同じ種別・バリアント・座標の枠があるかを数えた。動き出した敵は一致しないので、この数は参考値。 | 参考 |

全ページからの開始は、ゲーム自身が行わない始め方になる。そのため、表示範囲の一部がまだ用意されていないことがあった。

- **左端の列**：区間3の途中のページから始めると、左端から2列目までに512 px 先の列や隣の列が残っていた。120フレーム静止しても変わらなかった。
- **奇数行のページ**：開始表と途中復帰表はどの区間も偶数行のページを使う。奇数行のページから始めると、表示範囲の背景がまだ描かれていないことがあった。区間1のページ `$02F` から始めた写真では背景が真っ黒で、落下して行0に着いた後は、背景 RAM の列が ROM の位置から1つ右にずれていた。初期展開の書き込みそのものは ROM の表と一致しているので、展開後の行の取り込みで起きていると考えられる。原因の処理は未特定。

### 結果

150回の起動すべてで判定対象が一致した。

| 対象 | 結果 |
| --- | --- |
| 初期展開 | 150回すべて一致。67,968セルを比べた（他に、RAM や格子外を読むため予測できないセルが10,112）。 |
| 表示範囲 | 通常の開始と途中復帰の各7区間で、開始直後と歩行後の表示範囲がすべて一致し、左端に512 px 先の列が残る例もなかった。区間0の途中復帰と区間1の開始は、歩行中に落下などでプレイ状態が変わったため、歩行後は比べていない。その他のページからの開始では57回の記録が一致しなかった（上記の理由による参考扱い）。比べたタイルは合計37,602。 |
| パレット | 137回の記録のうち124回は循環中の色を除いて ROM と一致。残る13回は区間3。 |
| 固定配置 | 開始直後はほぼ全レコードの枠が見つかった。区間6の1件はボスで、開始直後にもう動いていた。 |

パレットは、区間0の開始で色42〜45（パレット5の2〜5番）が循環していた。区間3では色33〜36と39が循環し、37・38は120フレームの間変化しないまま ROM の値と違っていた。これらを書き換える処理は未特定。

## 種別の撮影

`tools/mame/capture-revg-types.py` は、区間ごとに通常の開始（右を時々押す歩行ありと静止の2回）と、カメラ範囲内の全ページからの開始（静止）で、計150回 MAME を起動する。各起動では無敵時間 `$AD` を保ったまま1,200フレーム進める。敵と足場の枠を毎フレーム調べ、ある種別が画面内に24フレーム続けていたら、その種別の最初の1回だけ画面写真を撮る。直後にその枠の Y だけを24 px 上げてもう1枚撮る。2枚で変わった画素がその枠の絵なので、近くにある別の物と取り違えない。

この方法で、敵14種別と足場6種別を区間ごとに計47件撮った。`$08` と `$0C` は、ボスのページ（区間0の `$0C`、区間1の `$1A`、区間2の `$4C`、区間3の `$58`）から右へ歩いて別に撮った。`$07`、`$0F`、`$10` はどの表にも現れないので撮っていない。`$07` は後で、効果音の送出元を調べる試行（`tools/mame/log-revg-sound-sources.lua`）の撮影に写った。

## 魔術師（種別 `$07`）

### 出現の条件

墓石を15回撃つと、その墓石の上に魔術師が出る。

| 位置 | 処理 |
| --- | --- |
| `$E26D–$E2A7` | 足場の初期化で、全種別の枠の `+$0A` に15を置く。 |
| `$F5FE–$F678` | 毎フレーム、足場30枠と自弾4枠（`$0540` から `$40` 刻み）の組を調べる。`$F679` の表で撃てる足場は種別 `$01`（墓石・岩）だけ。当たり枠は `$F67E + 8 × 種別` にあり、種別 `$01` は X が ±14、Y が足場の Y −8〜+4。重なると自弾を消し（状態 `$0201`）、足場の `+$0A` が0でなければ1減らす。 |
| `$F656–$F668` | `+$0A` が0になった回に、種別7のスケジューラ枠 `$0770` に墓石の X・Y を書いて有効にする。カウンタは0のまま残るので、1つの墓石から出るのは1回だけ。 |
| `$E9FB` → `$EBCB` | スケジューラは、空き敵枠 `$93` と種別ごとの残り数 `$0030 + 種別` がどちらも0でなければ、敵枠を取り、墓石の (X, Y + 16) に種別7を置いて `$37` を1減らす。 |

種別ごとの残り数 `$0030–$003F` は、区間の開始時に `$6F04` が bank4:`$4240` の表から写す。区間ごとに4行（各16バイト）あり、難易度 `$9A` の `$30` のビットで行を選ぶ。種別7はどの行でも区間2だけ2、ほかの区間は1なので、同時に出る魔術師は区間2で2体、ほかでは1体まで。

| 区間 | 種別 `$00`〜`$0F` の残り数（`$9A & $30` = 0 の行） |
| --- | --- |
| 0 | 3 4 4 3 3 1 1 1 2 6 6 3 1 2 4 4 |
| 1 | 4 5 3 4 3 1 1 1 2 6 8 3 1 2 4 4 |
| 2 | 2 5 4 5 2 2 1 2 2 6 8 4 1 2 4 4 |
| 3 | 6 5 3 6 6 3 1 2 2 6 8 5 1 2 4 4 |
| 4 | 1 5 2 6 3 3 1 2 2 6 8 2 1 2 4 4 |
| 5 | 1 3 3 6 6 4 1 2 2 6 8 5 1 2 4 4 |
| 6 | 3 5 3 6 6 3 1 2 2 6 8 5 1 2 4 4 |

ほかの行では一部の値が変わる。たとえば区間0のゾンビ（`$0B`）は、2行目以降で2になる。この表は FC 版で敵の数を減らす規則を決めるときの基準になる。

### 動作

`$C256` の更新処理は次の順に進む。

| 状態 | 内容 |
| --- | --- |
| `$0000` | プレイヤーのいる側を向き、絵を `$4EF3` にする。 |
| `$0100` | 効果音 `$03`。60フレームの間、2フレームおきに絵を消して点滅しながら現れる。 |
| `$0101` | 20フレーム待ってから絵を `$4EF7` に替え、敵弾の空き（`$A7`）があれば、自分の (X, Y − 10) に種別0の敵弾（呪文）を出す。さらに20フレーム待つ。 |
| `$0102` | 効果音 `$03`。60フレーム点滅して消え、`$0030 + 7` を1戻して枠を返す。 |
| `$0200` | 撃たれたとき。`$C36E` が効果音 `$14` を送り、絵を `$E87C` にして63フレーム数えた後、状態 `$0300` で枠を返す。逆アセンブルから読んだもので、魔術師を撃つ試行はしていない。 |

呪文は1フレームに約1.5 px（2フレームで3 px）、Y を変えずにプレイヤーの方へ進む。

### プレイヤーの変身

呪文に触れると、プレイヤーは緑のカエルになる。プレイヤーの状態の上位バイトは `$8F2A` の表で分岐し、`$04` がカエルの歩行（`$930E`）、`$05` がカエルの跳躍（`$937D`）。

| 段階 | 処理 |
| --- | --- |
| 始め | 状態 `$0400` の最初のフレームに、タイマー `+$18` を8にする。次のフレームから `$97D9` に入り、`$97E7` が効果音 `$02` を送り、`$DF` を `$81` にしてプレイヤー用パレットを1番に替え、タスク `$0801` を積む。16フレーム点滅した後に絵の表を `$9775`（歩行の絵 `$9779`、`$977F`、`$9785`、`$978B`）に替え、さらに16フレーム点滅してから `+$18` を7にする。 |
| 歩行 | `$934A` は左右だけを読む。速さは通常の歩行と同じ `$93B6` の表で、1フレームに1.125 px。射撃ボタン（`$10`）、上下、はしごは読まない。歩いている間は32フレームに1回、効果音 `$1E`。 |
| 跳躍 | `$907B` がジャンプボタン（`$20`）の押し始めを見て状態 `$0500` にする。`$93A5` が効果音 `$1E` を送り、絵を `$97B7` にして、縦の速さの表 `$93BA` で跳ぶ。横の向きは跳んだときの入力で決まる。 |
| 終わり | 64フレームに1回（`$21 & $3F` = 0）`+$18` を1減らし、1になったら `$983D` に入る。タスク `$0800` を積み、効果音 `$02` を送り、32フレームの点滅の後に `$DF` を `$80` にしてパレットを戻し、状態 `$0100` に戻る。戻すときの絵は鎧の状態 `$AC` で `$989F` の表から選ぶ。7から1までの6回の減算なので、変身は320〜384フレーム続く。 |

タスク `$0801` と `$0800` は、`$6188` の表の8番（bank3:`$527A`）を呼ぶ。HUD の武器枠を描き直し、`$0801` では枠だけ、`$0800` では今の武器 `$73` の絵も描く。変身中に武器枠が空になるのはこのため。

変身中に敵に触れると、通常の被弾と同じく状態 `$0300` に入って鎧を失い、着地すると変身は解けている。

### 計測

`tools/mame/measure-revg-magician.lua` は、区間0の開始地点から、X 256 の墓石をしゃがみ撃ちする。魔術師が出るまでは `$AD` で無敵にし、出た後は撃つのをやめて立ったまま待つ。墓石のカウンタ、スケジューラ枠 `$0770`、魔術師の枠、呪文の枠、プレイヤーの状態・絵・`$DF`、効果音の要求を変化のたびに出力する。立ったまま撃つと、弾は墓石の当たり枠の上を通り、カウンタは減らなかった。

| t | 出来事 |
| --- | --- |
| 51〜347 | しゃがみ撃ちが墓石に当たるたびにカウンタが15から1ずつ減り、効果音 `$0D` が鳴った。 |
| 347 | カウンタが0になり、`$0770` に (256, 62) が書かれた。 |
| 349 | 敵枠 `$0DD0` に魔術師が (256, 78) で出た。`$37` が1から0になった。 |
| 350 | 効果音 `$03`。 |
| 429 | 敵弾の枠 `$1470` に呪文が (256, 68) で出た。 |
| 450 | 効果音 `$03`。消え始めた。 |
| 511 | 魔術師の枠が返り、`$37` が1に戻った。 |
| 516 | 呪文が X 121 でプレイヤー（X 96）に触れ、プレイヤーの状態が `$0400` になった。 |
| 517 | 効果音 `$02`。 |
| 550 | 絵が `$9779` に替わった。 |
| 597 | ゾンビに触れて状態 `$0300`、効果音 `$01`。着地後の t = 632 に状態 `$0100`、絵 `$961E`、`$AC` = 1。 |

`REVG_MAGICIAN_SHIELD=1` で変身後も無敵にした試行では、t = 915 に `$02` が鳴り、t = 948 に状態 `$0100`、絵 `$9596` に戻った。t = 440 の撮影では、墓石の上で光る魔術師が写った。t = 600 の撮影では、変身中のプレイヤーはゾンビと重なって見分けられなかった。武器枠の表示は空だった。

`REVG_MAGICIAN_CONTROL=1` を加えると、状態が `$0400` になったフレームから数えて、40〜135フレームに右を押し、160と240フレームにジャンプ、200、208、216フレームに射撃を押す。この試行（変身は t = 516）の結果は次のとおり。

| t | 出来事 |
| --- | --- |
| 550 | 絵が `$9779` に替わった。 |
| 556〜654 | 右を押している間、X が96から203まで1フレームに約1.1 px 進んだ。絵は `$9779`、`$977F`、`$9785`、`$978B` を約6フレームずつ繰り返し、t = 563、595、627 に効果音 `$1E` が鳴った。 |
| 678 | 状態 `$0500`、効果音 `$1E` が2つ。X は変わらず、Y が62から最大102まで約40 px 上がり、t = 714 に着地して効果音 `$05`。 |
| 716〜733 | 射撃を3回押したが、自弾の4枠は空のままだった。 |
| 758 | 2回目の跳躍も同じ高さ（最大102）で、t = 794 に着地した。 |

無敵の間はプレイヤーの絵が1フレームおきに消えるので、撮影は奇数の t で行う。t = 601 の撮影ではゾンビの手前に緑のカエルが写り、t = 691 では跳んでいる緑のカエルが写った。

```powershell
$mameDir = "$env:USERPROFILE/tools/mame/mame0289"
$env:REVG_MAGICIAN_SHIELD = '1'
$env:REVG_MAGICIAN_FRAMES = '1000'
$env:REVG_MAGICIAN_SNAP = '440,600'
& "$mameDir/mame.exe" makaimurg -rompath reference -noreadconfig -video none -sound none -nothrottle -skip_gameinfo -autoboot_delay 0 -autoboot_script tools/mame/measure-revg-magician.lua -cfg_directory build/revg-magician/cfg -nvram_directory build/revg-magician/nvram -snapshot_directory build/revg-magician/snap
Remove-Item Env:REVG_MAGICIAN_SHIELD, Env:REVG_MAGICIAN_FRAMES, Env:REVG_MAGICIAN_SNAP
```

カエルの操作を試すには、上の例の `REVG_MAGICIAN_SNAP` を `'561,601,691'` にし、`$env:REVG_MAGICIAN_CONTROL = '1'` を加える。`REVG_MAGICIAN_FRAMES` は800にする。

## 未解明の点

- 名前に「？」を付けた種別（`$00`、`$02`）と、呼び名を決めていない種別（`$04`、`$09`、`$0E`、`$12`）。見た目は確かめたが、元のゲームの呼び名とは照合していない。ファンの wiki には Woody Pig、Petite Devil、Blue Killer などの名前があるが、出典が公式でなく、各ページも読めなかった。公式資料（インストラクションカードや攻略本）での照合が必要。
- 足場 `$00` は4つのバリアントとも MAME で確かめた。武器と、敵の落とし物の得点アイテムの取得は逆アセンブルから読んだもの。
- 円盤が消す `$74–$77` のビットを立てる処理が他の版にあるか。Rev G では常に0で、円盤の消去は効果がない。
- 岩（区間2の種別 `$01`）を撃っても魔術師が出るか。初期化 `$E26D` と命中処理 `$F5FE` は区間もバリアントも見ず、種別 `$01` ならカウンタ15を置いて数えるので、コードの上では岩からも出る。区間2の種別7の上限が2なのもこれと合う。MAME では試していない。
- 跳躍の縦の速さの表 `$93BA` の読み方と、横に跳んだときの距離。跳躍は真上に跳ぶ試行しかしていない。
- 足場 `$03` のバリアント1の絵。区間1の撮影では画面に変化がなかった。
- グループから参照されない26個のパターンの用途。
- `$E997` が種別と難易度から引く bank2:`$5DED` の表（スケジューラの `+$0C` に置く）の意味。
- パレットの一部の色を実行中に書き換える処理。
- 奇数行のページから始めた後の行の取り込みで、背景がずれたり描かれなかったりする理由。
- 扉など、撮影で出てこなかった仕掛けがどの処理に当たるか（隠し鎧は足場 `$00` のバリアント0）。

## 再現手順

```powershell
python tools/mame/extract-revg-stages.py --render
python tools/mame/verify-revg-stages.py --mame "$env:USERPROFILE/tools/mame/mame0289/mame.exe"
python tools/mame/capture-revg-types.py --mame "$env:USERPROFILE/tools/mame/mame0289/mame.exe"
```

撮影ツールは `build/revg-types/` に、区間ごとの最初の撮影を並べた `types.json` と、撮影と持ち上げ後の画像を並べた `types.png` を書く。ボスのページの撮影は、`REVG_TYPES_SECTION`、`REVG_TYPES_PAGE`（16進）、`REVG_TYPES_WALK=1` を付けて `capture-revg-types.lua` を直接起動する。

抽出ツールは ROM 3個を MAME の SHA-1 と照合し、`build/revg-stages/` に次のファイルを書く。

| ファイル | 内容 |
| --- | --- |
| `world.json` | 画面 ID の格子、ページ表、地形判定表（接地・右壁・左壁・はしご）、使われている全画面の 16×16 タイル（上の行から順。タイル番号は10ビット、属性は bit 5–0） |
| `sections.json` | 区間ごとの座標・カメラ範囲・タイマー・ボス残数・同時枠・固定配置 |
| `enemies.json` | 敵と足場の種別名、敵グループとパターン |
| `section0-map.json` 〜 `section6-map.json` | 区間のカメラ範囲を切り出したタイルマップ（上の行から順） |
| `section0.png` 〜 `section6.png` | 確認用の描画。各ページは自分のパレット番号を、0なら区間の開始ページの番号を使う |
| `section0-ground.png` 〜 | 接地判定の高さを紫の線で重ねた描画 |

照合ツールは `tools/mame/dump-revg-stage.lua` を使い、1ページあたり1回 MAME を起動する。`REVG_STAGE_SNAPSHOT=1` を付けて Lua を直接起動すると、記録した時点の画面写真を `-snapshot_directory` に保存する（フォルダは先に作っておく）。
