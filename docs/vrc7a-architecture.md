# VRC7a 移植仕様とメモリ設計

512 KiB 版（NES 2.0 Mapper 85 / Submapper 2、PRG 512 KiB、CHR-RAM 8 KiB、WRAM 8 KiB）を本編の開発対象とし、アーケード版『魔界村』（国内版 Revision G）のゲーム構造を VRC7a 向けへ段階的に移植するための仕様採否とメモリ配置を定める。

## 1. 移植仕様の採否（推奨構成）

[国内版 G の計測結果](revision-g.md) および [6809 ROM マップ](revision-g-rom-map.md) の実測値を基準とし、以下を採用する。ステージ・グラフィック・音楽・効果音はすべて新規自作する。

| 項目 | 採用仕様 | 備考・段階導入 |
| --- | --- | --- |
| ライフ・鎧 | **2段階ライフ（鎧 → 裸 → ミス）**。被弾時ノックバックと無敵時間（120F）、ドロップ／隠しによる鎧回復を採用する。 | 時間切れは鎧状態に関わらず1ミス。被弾と時間切れの同フレーム発生時は残機減算を1回に抑える。 |
| プレイヤー操作 | **アーケード準拠**：ジャンプ中の横方向制御不可（踏み切り時の向き・速度で固定）、地上射撃時の移動停止（15F）、しゃがみ・しゃがみ撃ち、はしご昇降、着地同フレームの再ジャンプ不可。 | 物理定数は 60 Hz NTSC と FC の画面解像度（256×240、上端 32 px HUD）に合わせて調整する。 |
| 武器システム | **複数武器の切り替え**（槍・短剣・松明・斧・必須武器相当）。同時発射数制限、放物線軌道や地面効果、敵・ツボからのドロップを採用する。 | 最初は水平単発＋放物線1種の2種で枠組みを検証し、順次追加する。 |
| 地形・動的足場 | **2次元メタタイルマップ**で穴・壁・複数階層・片方向足場・はしごを扱う。加えて**移動足場**（プレイヤー運搬）と**障害物兼足場**（墓石相当）を動的オブジェクトとして実装する。 | 現行の1次元ハイトマップ（`src/terrain-data.inc`）から2次元形式へ一括移行する。 |
| 敵出現と難易度 | 固定配置に加え、**スクロールページ連動の出現スケジューラ**（同時枠上限・待機タイマー・画面外枠回収）と**難易度ランク**を採用する。 | 枠満杯時の待機停止・復帰時の初期化を Mesen で検証する。 |
| ボス・区間進行 | カメラ固定、複数部位または耐久管理、撃破後の鍵／出口解放で次ステージへ移行する。大型ボスは 8 KiB CHR-RAM・16×16 属性・走査線8スプライト制限に収める（必要に応じ BG 描画を併用）。 | 戦闘中の被弾再開でボス・出口を初期化する。 |
| ステージ構成 | **段階構築**：まず「横スクロール主体1面＋縦方向進行1面」の2ステージで全システム（マップ・鎧・複数武器・移動足場・スケジューラ・ボス・BGMドライバ）を完成させ、その枠組みで**全7区間（1〜6面＋最終ボス）と2周目・必須武器分岐・真エンディング**へ拡張する。 | 現行2コースは診断および移行時の回帰ベースラインとして維持する。 |
| スコア・残機 | 初期残機3（プレイ中含む）、各ステージ制限時間120秒、スコア加算とエクステンドを採用する。 | HUD（上端32 px）にステージ・残機・時間・武器・スコア等を収める。 |
| 音源 | **VRC7a FM 6声（カスタム音色1枠共有）＋本体 APU** の専用 BGM/SE ドライバを実装する。曲切り替え、SE によるチャンネル割り込みと復帰を管理する。 | `$9010` 後 6 サイクル、` $9030` 後 42 サイクルのウェイト規約を厳守し、メイン処理側で更新する。 |

## 2. PRG-ROM（512 KiB / 64バンク）配置規約

### 現状の実測推移（512 KiB 版）

| マイルストーン | `FIXED`（/ 8,186 B） | `BANK3`（/ 8,192 B） | `BANK8`（/ 8,192 B） | `BANK12`（/ 8,192 B） | `WRAM`（/ 8,192 B） | `ZEROPAGE`（/ 256 B） | `CHR-RAM`（/ 8,192 B） |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 設計ベースライン（移行前） | 5,834 B（残 2,352 B） | 0 B | 0 B | 0 B | 0 B | 93 B | 864 B |
| Section 3 完了（タスク 3-1〜3-5） | 6,177 B（残 2,009 B） | 4,593 B | 0 B | 1,024 B | 172 B | 103 B | 1,072 B |
| Task 4-1 完了（音源ドライバ） | 6,263 B（残 1,923 B） | 4,650 B | 1,734 B | 1,024 B | 219 B | 105 B | 1,072 B |

固定バンクの残量は 1,923 B。**今後の本編機能（データ駆動ステージ表・縦スクロール・拡張敵/ボス AI・ステージデータ）は固定バンクへの追加を原則ゼロに抑え、切り替えバンク（`BANK3`/`BANK4`, `BANK8`, `BANK12+`）へ分離する**。

### 切り替え窓の役割分担

VRC7a の3つの 8 KiB PRG 窓を用途別に固定運用する。

| CPU 領域 | VRC7 レジスタ | 役割 |
| --- | --- | --- |
| `$8000–$9FFF` | `$8000` | **データ窓**：現在ステージのヘッダ、2次元マップ、ブロック定義、敵配置表、CHR パターン、曲データ。 |
| `$A000–$BFFF` | `$8010` | **本編ロジック窓**：プレイヤー物理・地形判定、敵・ボス AI、スケジューラ、ステージ進行処理。 |
| `$C000–$DFFF` | `$9000` | **描画・サウンド窓**：BGM/SE ドライバ、メタタイル／列・行展開ルーチン。 |
| `$E000–$FFFF` | 固定（Bank 63） | **カーネル固定バンク**：リセット、NMI、IRQ、OAM DMA、VRAM 転送、パッド入力、バンク切替トランポリン、VRC7 書込、32 KiB 診断コア。 |

### バンク番号の割り当て予定（64バンク：Bank 0〜63）

すべてのバンクの先頭1バイト（オフセット `$0000`）は、起動時の全バンク検査（`check_bank`）との互換性を保つため、引き続き **`$80 + bank_index` の識別バイト**を配置する。

| バンク範囲 | 容量 | 用途 |
| --- | ---: | --- |
| Bank 0〜1 | 16 KiB | 既存診断コース（元コース／追加コース、32 KiB 版と共有） |
| Bank 2 | 8 KiB | 診断用予約（既存 32 KiB 版の初期 `$C000` タグ検査を維持） |
| Bank 3〜7 | 40 KiB | 本編ロジック（プレイヤー・地形判定・武器・動的足場・敵 AI・ボス AI・スケジューラ） |
| Bank 8〜11 | 32 KiB | 描画展開ルーチン・BGM/SE ドライバおよび楽曲・音色データ |
| Bank 12〜27 | 128 KiB | ステージデータ（ステージヘッダ、2次元ブロックマップ、敵配置・出現グループ表：最大7区間＋余裕） |
| Bank 28〜43 | 128 KiB | CHR-RAM 転送用パターン（ステージ別背景・スプライト・ボス・エンディング） |
| Bank 44〜62 | 152 KiB | 予備（追加ステージ・演出・デモ・テスト用） |
| Bank 63 | 8 KiB | 固定バンク（`$E000–$FFFF`） |

### バンク呼び出し規約（トランポリン）

- `ZEROPAGE` に各窓の現在バンク番号シャドウ（`prg_bank0`, `prg_bank1`, `prg_bank2`）を保持する。
- NMI / IRQ ハンドラは PRG バンクレジスタを変更しない（描画転送とスクロール設定のみ固定バンク＋RAM/WRAM で完結させる）。
- 固定バンクにバンク切替ラッパー（`call_bank_a000` / `select_bank_8000` 等）を置き、呼び出し前のシャドウをスタック退避して復帰時に復元する。

### 32 KiB 診断版との分離方針

- 既存の 32 KiB 診断 ROM と `tools/mesen/*-smoke.lua` の全回帰試験を維持する。
- 512 KiB 本編のコード・データは Bank 3 以降（`PRG_ROM_UNITS = 32` 時のみリンク）と専用 `.inc` ファイルへ分離し、固定バンク内の `.if PRG_ROM_UNITS = 32` 分岐は最小限のディスパッチ入口（タイトルの連続プレイ開始・フレーム更新フック等）に限定する。

## 3. RAM / WRAM（8 KiB）メモリマップ

| 領域 | アドレス | サイズ | 用途 |
| --- | --- | ---: | --- |
| ZEROPAGE | `$0000–$00FF` | 256 B | フレームカウンタ、入力、カメラ座標（16bit X/Y）、スクロール制御、バンクシャドウ、一時ポインタ、プレイヤー主要状態。 |
| STACK | `$0100–$01FF` | 256 B | 6502 ハードウェアスタック（バンク切替退避含む）。 |
| OAM | `$0200–$02FF` | 256 B | スプライト DMA バッファ。上位枠はプレイヤーと危険な敵弾に優先割当、残りをフレーム毎ラウンドロビン。 |
| BSS | `$0300–$07FF` | 1,280 B | NMI 転送キュー（行・列・属性・HUD 更新バッファ）、パレットシャドウ、スクロール管理、サウンド基本ワーク。 |
| WRAM | `$6000–$60FF` | 256 B | キャンペーン進行状態・ステージヘッダキャッシュ（起動時 `$6000` 検査後に初期化）。 |
| WRAM | `$6100–$68FF` | 2,048 B | エンティティ配列（SoA 形式：16ビット X/Y、8.8 速度、状態、タイマー、耐久値、種別・フラグ）。プレイヤー・自弾・敵・敵弾・動的足場・アイテムを収容。 |
| WRAM | `$6900–$6BFF` | 768 B | 敵スポーン・スケジューラ状態、出現予約テーブル、撃破済み固定オブジェクト管理、難易度ランク。 |
| WRAM | `$6C00–$77FF` | 3,072 B | 現在ステージの展開済み2次元メタタイル／属性キャッシュ（高速な当たり判定・スクロール列/行更新用）。 |
| WRAM | `$7800–$7FFF` | 2,048 B | BGM/SE シーケンサワーク、一時展開バッファ、予備領域。 |

## 4. ステージヘッダと2次元マップ形式（タスク 3-1 設計）

現行の `src/terrain-data.inc`（1列＝1バイトの1次元ハイトマップ、幅48列固定）を廃止し、以下の形式へ移行する。

### ステージヘッダ（各ステージデータバンク先頭、識別タグの直後）

- **寸法**: 横幅（16 px メタタイル列数、最大 255 列＝4,080 px）、縦幅（16 px メタタイル行数、最大 64 行＝1,024 px）
- **開始・復帰地点**: 開始座標（16bit X, 16bit Y）、チェックポイント判定 X（16bit）、復帰座標（16bit X, 16bit Y）、復帰カメラ初期位置（16bit X, 16bit Y）
- **カメラ境界**: カメラ X 最小/最大（16bit）、カメラ Y 最小/最大（16bit）
- **ゴール／ボス境界**: ゴール（またはボス固定）X/Y 座標（16bit）
- **参照 ID**: 背景パレットテーブル、ブロック／メタタイル定義、敵配置表、BGM ID

### 2次元メタタイル属性（1バイト／タイル種別）

各 16×16 メタタイルに属性バイトを紐付け、描画と地形判定を単一の定義から参照する。

- `bit 0–1`: 背景パレット番号（0〜3）
- `bit 2–4`: 地形種別
  - `0`: 空気（通過可能）
  - `1`: 固体（床・天井・左右壁）
  - `2`: 片方向足場（上からのみ接地、下から通過可）
  - `3`: はしご（昇降可能、上端は片方向足場として扱う）
  - `4`: 穴／即死領域（水路・奈落）
- `bit 5`: 前景優先フラグ（灯籠門のようにプレイヤーが手前／後ろを通過する演出用）
- `bit 6–7`: 予約（崩れる床・特殊ギミック等）
