# 国内版 Revision G の 6809 ROM マップ

対象は MAME 0.289 の `makaimurg`。アドレスは CPU に見える位置を表し、切り替え窓の参照には `bank3:$553A` のようにバンクを付ける。

## ROM の配置

| 領域 | CPU アドレス | MAME の `maincpu` 内オフセット | ROM 内の範囲 |
| --- | --- | --- | --- |
| fixed | `$6000–$7FFF` | `$06000–$07FFF` | `mj04g.bin` の後半 8 KiB |
| fixed | `$8000–$FFFF` | `$08000–$0FFFF` | `mj03g.bin` 全体 |
| bank0 | `$4000–$5FFF` | `$10000–$11FFF` | `mj05g.bin` の `$0000–$1FFF` |
| bank1 | `$4000–$5FFF` | `$12000–$13FFF` | `mj05g.bin` の `$2000–$3FFF` |
| bank2 | `$4000–$5FFF` | `$14000–$15FFF` | `mj05g.bin` の `$4000–$5FFF` |
| bank3 | `$4000–$5FFF` | `$16000–$17FFF` | `mj05g.bin` の `$6000–$7FFF` |
| bank4 | `$4000–$5FFF` | `$04000–$05FFF` | `mj04g.bin` の前半 8 KiB |

`$3E00` への書き込み値が4なら bank4、それ以外は下位2ビットで bank0〜3を選ぶ。上の配置は MAME のメモリマップとローカルの `-listxml makaimurg` で照合した。さらに起動時の自己診断と同じ方法で計算した16ビット加算チェックサム8個が、`bank3:$5FF0–$5FFF` の期待値とすべて一致した。順序は bank4、3、2、1、0、固定 ROM の `$6000–$7FFF`、`$8000–$BFFF`、`$C000–$FFFF`。bank3 の加算範囲は `$4000–$5FEF`。[MAME のバンク選択](https://github.com/mamedev/mame/blob/mame0289/src/mame/capcom/gng.cpp#L211-L220) · [MAME のバンク配置](https://github.com/mamedev/mame/blob/mame0289/src/mame/capcom/gng.cpp#L496-L500)

## 起動と割り込み

| 起点 | 種別 | 確認した内容 |
| --- | --- | --- |
| fixed:`$FFF2–$FFFF` | ベクタ表 | IRQ は `$FFF8 → $65C4`、リセットは `$FFFE → $6000`。残りの5語は `$FFFF`。 |
| fixed:`$6000`、`$6073` | コード | リセットから初期化に入り、`$6073` で bank3 を選び、`$607A` から `bank3:$553A` の自己診断に移る。 |
| bank3:`$553A`、`$55F9–$560B`、`$560C–$5659` | コード | 自己診断が `$560C` から78バイトを RAM の `$1A00–$1A4D` にコピーして実行する。コピー先の `$1A0D` が bank4→3→2→1→0 の順で窓を切り替える。チェックサム照合のため bank3 への切り替えも間に入る。 |
| fixed:`$60DA–$60FB`、bank4:`$4000–$40FF` | コード、コピー元のデータ | bank4 を選択してから、各128バイトを RAM の `$0480` と `$16B2` へコピーする。 |
| fixed:`$65C4`、`$65E8–$65FA` | コード | IRQ の入口からスプライトバッファ書き込みや更新処理に進む。bank3 を選択して `$65F3` で間接呼び出しし、`$D9` の値でバンクを戻して `RTI`。 |
| fixed:`$65BC–$65C3` | IRQ の呼び出し先テーブル | `$02` を2倍して参照するビッグエンディアンのアドレス列。先頭3件の fixed:`$684F`、fixed:`$694D`、fixed:`$6F22` は起動から1P開始までに実行時の参照を確認した。4件目の `bank3:$5671` は静的に確認した。 |
| fixed:`$65FB–$660C`、`$660D–$6618` | コード、2つのテーブル | `$21 & 3` を使い、`$660D` からバンク選択値を読み、`$6611` からジャンプ先を得る。`$6604` の書き込みで値3と4を観測した。 |

## 1P 開始地点のプレイヤー更新

以下は第1面の開始地点で通常操作が可能になった後の経路。アドレスはすべて固定 ROM を指す。テーブルの項目は16ビットの分岐先として読み、MAME で通った入口と照合した。

| 処理 | 入口と分岐 |
| --- | --- |
| 入力の取り込み | IRQ `$65C4` が `$65D6` で `$6772` を呼ぶ。P1 の `$3001` と P2 の `$3002` を反転して、押されたビットが1になるよう `$0046` と `$0048` に置く。プレイ中の `$691C` が前回の入力を `$004B` から `$004C` に移し、P1 の今回の入力を `$004B` に入れる。 |
| プレイ中の呼び出し | IRQ の分岐先 `$6F22` から、`$0005`、`$0008`、`$000B` に対応する表を順に使い、`$6F54 → $7097 → $70F3` へ進む。`$70F3` が入力を選び、`$7E6D → $8F0E` でプレイヤーを更新した後、`$EE73` で戦闘判定を呼ぶ。 |
| プレイヤーの状態 | `$8F0E` がレコードの基準を `X = $0510` に置く。`$8F1E` は `$0500` が0なら戻り、活動中は `$0503` で分岐する。通常地上の `1` は `$8FD3`、ジャンプの `2` は `$93CA`、被弾直後の `3` は `$995F` に進む。地上の通常歩行は `$0504 = 0` で `$8FDF` に入る。 |
| 平地の左右入力 | `$9233` は `$004B & $004C` の左 `0x02`、右 `0x01` の順に調べる。有効な方向がなければ `$050E` を0にする。方向が変われば `$050E` と向き `$051E` を更新する。`$9265` から横の判定を経て `$92DA` が X 座標を更新する。計測した右歩行は毎回 288/256 px。 |
| ジャンプ入力 | 地上の `$907B` は `$004B & ~$004C & 0x20` が立つと `$9084` で `$0503` を1から2にし、`$0504–$0505` をクリアする。次の更新で `$93CA` が既に設定された `$050E` を使い、`$9415` でジャンプを初期化して `$0504` を1にする。静止状態から右とジャンプを同時に押した場合、右が今回と前回でそろう前にジャンプが受理され、空中の横移動は0だった。 |
| 接地と壁 | 地上では `$903F` が `$8B0A` を呼び、キャリーが立てば `$9052` で Y を補正する。タイルに接地していなければ `$9E14` で足場を調べる。両方に接地しない場合は `$0504` を進める。右壁 `$8B7D`、左壁 `$8BAF` は、地上の `$9265` 系と空中の `$93CA` 系から利用される。壁に当たると、呼び出し側が返された食い込み量を使って X を補正する。 |
| 上昇と着地 | `$0504 = 1` の `$942B` から `$94EA` が Y を進め、上向き速度が閾値を下回ると `$0504` を2にする。下降時の `$946A` は `$8B0A` のタイル判定でキャリーが立つと `$952D` に進む。通常ジャンプでは Y を補正し、`$0503` を1、`$0504` と `$050E` を0に戻す。 |
| 被弾 | `$EE73` は `$0021` の bit 0 が0のときに `$F057` の本体判定を呼び、1のときに `$F48C` の敵弾判定を呼ぶ。両方とも `$00AD = 0` と `$0500` の bit 0 を入口で確認する。本体の `$F0A1` と敵弾の `$F4E2` からは、鎧状態を1から2、処理状態 `$0503` を3にする。開始地点の無入力試行では、通知1273の後に `$F0A1`、次の更新で `$995F` を通った。敵弾側は逆アセンブルと既存の被弾計測で照合した。 |

### 平地ジャンプの再入力

初回のジャンプは通知1141の後に受理され、通知1177の後の更新で着地した。表の番号はボタンを書き換えた通知から1つ後で、CPU が押下を読んだ更新を示す。再押下はすべて1回の入力読み取りにだけかかるようにした。

| 試行 | 2回目の押下を読んだ更新 | 結果 |
| --- | --- | --- |
| `jump_hold` | 初回から保持 | 着地後、観測終了の通知1190まで再ジャンプなし。 |
| `jump_before_land` | 1176 | 再ジャンプなし。 |
| `jump_on_land` | 1177（着地と同じ更新） | 再ジャンプなし。この更新では `$952D` を通り、翌更新の `$907B` では押下が前回値にだけ残っていた。 |
| `jump_after_land` | 1178（着地の次の更新） | `$9084` で受理され、通知1180で `$0504 = 1` を観測した。 |

## 背景タイルの展開と地形判定

第1面の初期表示では、`$62AB` 系が bank2 の画面 ID を使って周辺の背景を展開する。`$006C` はその画面 ID 列を指す。ここでの画面 ID は、256×256 px 分の背景を選ぶ値を指す。

| 段階 | 読み書きの内容 |
| --- | --- |
| bank2 で画面を選ぶ | `$6309` が bank2 を選び、`$4200 + 2 × 画面 ID` から bank1 内のレコード表の先頭を16ビットで読む。 |
| bank0 でブロックを選ぶ | `$6378` が `$4000 + 64 × 画面 ID` を求める。画面全体では `$6328–$633B` が8列×8行を展開し、`$6346` が bank0 の列内を下へ進みながら、32×32 px ブロックの番号を1バイトずつ読む。`$62F0–$6303` のループでは幅を4列に絞る。 |
| bank1 で16 px タイルに展開 | `$6353` が bank1 を選び、レコード表の先頭にブロック番号の8倍を足した位置から8バイトを読む。前半4バイトはタイル番号、後半4バイトは対応する属性。それぞれ左下・左上・右下・右上の順に並ぶ。`$635E–$6373` は番号を `$2800–$2BFF`、属性を対応する番地の `+$0400` に書く。 |
| 表示範囲の列更新 | `$8033` 系では `$80F1` などで bank2 のポインタを引き、`$80C5` と `$818B` が bank0 のブロック番号から bank1 のレコードを読み直す。列を作業 RAM に置き、`$8514` のループがタイル番号と属性を背景 RAM に転送する。 |

初回デモでは通知1039の後に、bank2 の `$4200` から bank1 の表の先頭 `$4000` を読み、bank0 の `$4000` のブロック番号0から bank1 の最初の8バイトを選んだ。その8バイトが初期展開の4セルと属性に対応することをタップで照合した。1P 開始後に観測した床のセル `$28AD` と属性 `$2CAD` の直近の書き込み元は、列転送の `$851B` と `$8517` だった。

### 判定点から背景 RAM と境界表を引く

`$8C35` は判定点の整数座標 X・Y からタイル番号の番地を求める。下式の Y はプレイヤーの座標系で上が正。32×32タイルの背景 RAM は列優先で、512 px 周期で折り返す。

```text
列 = (X >> 4) & 31
行 = ((Y XOR 0x00FF) >> 4) & 31
タイル番号 = RAM[0x2800 + 32 × 列 + 行]
属性       = RAM[0x2C00 + 32 × 列 + 行]
```

接地の2点目は `$8B43–$8B60` で1点目の番地を横にずらす。ずらす量は姿勢 `$051F` による `$8BDD` の表で決まる。

| 判定 | 候補と境界 |
| --- | --- |
| 共通 | 属性の `0xC0` が非ゼロなら、その候補は境界表を読まずに外れる。残った候補は、タイル番号を符号付き8ビットにして bank4 の表の基点に足す。表の値0も候補から外れる。 |
| 接地 `$8B0A` | 基点は `$448E`。タイル内 Y が高さの上限以下ならキャリーを立てる。1点目の不成立時に2点目を試す。 |
| 右壁 `$8B7D` | 基点は `$458E`。右16 px・下8 px のタイル内 X が境界値以上なら接触。 |
| 左壁 `$8BAF` | 基点は `$468E`。左16 px・下8 px のタイル内 X が境界値以下なら接触。 |

1P の通知1138の後に、判定点 (88, 46) がタイル番号 `$06`・属性 `$09` の `$28AD` に対応し、bank4 の `$4494` から高さ14を読んだ。左歩行では、属性 `$C2` の候補を通過し、次の更新ではタイル番号 `$A3` が符号付きの `−93` として扱われ、実際の読み出し先は `$4631` だった。[通常地面の着地境界](revision-g.md#通常地面の着地境界) · [壁の左右判定](revision-g.md#壁の左右判定)

## 敵と足場の配置

第1面の先頭のゾンビと墓石、および区間1の移動足場1基を調べた。座標はワールド座標で Y の正は上。通知番号は MAME のフレーム通知を数えた値。オブジェクト枠は各レコードの先頭から16バイト進んだアドレスを X・Y・U に入れて参照する。たとえば墓石のレコードの先頭は `$1380` で、下表の枠ポインタは `$1390`。

### 墓石と移動足場の初期化

`$6DA4` 系で足場用の空き枠リストを作る。枠ポインタは `$1010` から `$13B0` まで、間隔は `$20`。区間初期化の `$6E76` が bank2 の `$4B02 + 4 × RAM[$72]` からビッグエンディアンでリストのアドレスを読み、先頭1バイトを件数として使う。`$8C78` は空き件数 `$98` を検査し、空きリスト `$96` が指す枠を末尾側から取得する。

各6バイトのレコードは種別、バリアント、16ビット X、16ビット Y の順。`$6E91–$6EA4` が順に枠ポインタから `+$05`、`−$0E`、`−$0A`、`−$07` へ書き込み、`−$10` を1にする。

| 対象 | bank2 のレコード先頭 | 枠ポインタ | 種別・バリアント | 初期座標 | 配置を観測した通知 |
| --- | --- | --- | --- | --- | --- |
| 開始地点の墓石 | `$4B23` | `$1390` | `$01`・`$01` | (256, 62) | 1P は1020と1058。無入力デモは1038と1076 |
| 区間1の三つ目の水路の移動足場 | `$4C6F` | `$10D0` | `$04`・`$03` | (6416, 56) | 8473と8511 |

移動足場では、通知8513に `$E2B4` 系が種別から bank4 の `$5978` を、バリアントから `$5992` を引き、移動指示のポインタ `$5A2E` を枠の `+$06` に格納した。通知12361に `$E3CA` 系が同じ位置から最初の指示を読み、移動量を選ぶ値2と継続値10をセットした。[墓石の接地境界](revision-g.md#墓石の接地境界) · [移動足場の接地と移動](revision-g.md#移動足場の接地判定と三つ目の水路)

### 先頭のゾンビの出現

1. `$8DE7` 系が bank2 の `$4300 + 4 × word($91) + 3` からグループ番号を読み、`$0670` に渡す。開始地点では `$4303` から0を読んだ。`$70FC → $E898 → $E8B7` の処理が bank2 の `$4FE0` のポインタ表からグループを引き、`$50B6` にある件数を読み取った。
2. `$E8F0` 系はグループ内の2バイトをニブルに分けてスケジューラの枠とそのフィールドに展開する。今回の枠ポインタは `$07F0`。`$E976 → $E9D0` が種別とパターン番号から bank2 の `$5188` を基点とするポインタ表を引いた。先頭のゾンビでは `$522A` が `$56DD` を指し、件数を読んだ次の `$56DE` を枠の `+$0E` に格納した。
3. `$E9FB` 系は敵枠の空き数と種別別の残り数を検査する。種別 `$0B` は `$EBF1` を経由し、`$8C5F` で敵用の空きリスト（件数 `$93`・ポインタ `$94`）から枠を取る。敵枠の間隔は `$30` で、今回取得した枠ポインタは `$0E00`。
4. この種別の X はカメラ X `word($9C)` に128を足し、`$56DE` の16ビット値をスケジューラの方向によって加減する。Y は `word($A2)` から取る。`$EAEC` 系がバリアントと種別を書き込み、枠を有効にする。最初の配置は1P の通知1062、デモの通知1080で、どちらもカメラ X=0、オフセット144、初期位置 (272, 62) だった。次の更新で敵枠の状態が1から2に変わる。[ゾンビの出現から歩行・描画まで](revision-g.md#1p-プレイの先頭のゾンビ)

## 区間の開始・復帰・終了

区間番号は `$72`。通常開始と途中復帰で同じ初期化 `$6C67` を通り、`$81` が復帰表の選択、`$72` が表内のレコードの選択に使われる。以下の処理は固定 ROM にある。鍵を使った区間移行は MAME 0.289 の既定 DIP、1周目の区間0〜2で照合した。全区間の復帰表は[別の試行](#全区間の途中復帰とタイマー)で照合した。

### 開始・復帰座標とカメラ

- `$6D26` は `$6CEA` のポインタ表から、`$81=0` で開始表 `$6CEE`、`$81=1` で途中復帰表 `$6D0A` を選ぶ。区間あたり4バイトで、背景ページ番号（ビッグエンディアン16ビット）、ページ内 X、ページ内 Y の順。各表には区間0〜6のレコードがある。
- `$6D37–$6D73` はページ番号から `$4000` を引いた値を `$91–$92` に保存する。下位5ビットが横方向のページ、残りの上位ビットが縦方向のページを表す。各軸でページ位置を256倍し、ページ内の値を足してプレイヤー座標にする。
- `$6CC8` は `$6CAC + 4 × 区間番号` から X 下限、X 上限、Y 上限、Y 下限の4バイトを読み、それぞれ256倍して `$58`、`$5A`、`$5C`、`$5E` に入れる。通常追従で X は `$8017` と `$8293`、Y は `$8575` と `$85AA` が境界を調べる。X 上限は移動前に比較するので、限界をまたぐ更新で X が上限を越える例がある。[区間1のボス戦で観測した上限越え](revision-g.md#区間1のボスと区間移行)
- `$ECA4` 系は `$81=0` の更新で、プレイ用カメラ X `word($9C)` を `$ECE4 + 2 × 区間番号` の16ビット値と比較する。`$ECBD` は同値を通過扱いにせず、境界を超えたときに `$ECDB` が `$81=1` を書く。引き返す動きではフラグを戻さない。通常の区間移行では `$6C55` がクリアする。タイマーは開始・復帰の初期化 `$6ED8` 系で表から設定し、`$ECCF` 系でもチェックポイント到達時に途中復帰用の値へ切り替える。タイマーが0になると `$EC81` 系が時間切れを通知する。

### ボス撃破から次の区間へ

1. `$6ED8` は `$6ED1 + 区間番号` からボス残数 `$B6` の初期値を読む。`$E78C` が残数を減らし、0になると `$E79B` が進行状態 `$08` を2にする。区間1の2体戦では、1体目の消滅時に残数1、2体目の消滅時に0を記録した。
2. 通常の鍵を使う経路では `$72CC` 系がプレイヤーの接近を待つ。区間0〜3は X がカメラ X 上限−48以上、区間4と区間5の通常経路では Y がカメラ Y 上限＋32以上。鍵の目標 X はカメラ X 上限＋37。`$730D` はプレイヤーのジャンプ状態を除外し、`$7315–$733E` は鍵の目標 X と当たり判定用 Y `word($0550)` に対し、両軸で差が±8以内のとき取得を通知する。
3. 取得後の演出を経て `$7399–$73A8` が区間番号を1つ進め、チェックポイントをクリアして初期化に戻す。1周目の区間0→1と区間1→2では、鍵の取得から更新まで両方とも181フレームだった。

`$711F` には通常の鍵処理を呼ぶ `$712F` 以外の分岐もある。区間5は `$73` が3のときに通常経路を使い、それ以外は `$716B` 側へ進む。区間6は `$71C3` 側に分岐する。[終盤の分岐](#終盤の分岐)

## 全区間の途中復帰とタイマー

`$ECBD` でカメラ X が境界より大きい場合にだけ `$ECDB` が途中復帰フラグを立てる。その直前に `$ECD5–$ECD7` が途中復帰用タイマーを設定する。時間切れ処理 `$EC81` を経て再初期化すると、`$6D26` と `$6ED8` 系が同じフラグで座標表とタイマー表を選ぶ。座標とタイマーの初期値は以下のとおり。

| 区間 | カメラ X の範囲 | 境界 | 開始座標 (X, Y) | 途中復帰座標 (X, Y) | タイマー初期値 開始 → 途中復帰 |
| --- | --- | ---: | --- | --- | --- |
| 0 | 0〜3328 | 1792 | (96, 64) | (1920, 64) | 120 → 120 |
| 1 | 3584〜6912 | 4608 | (3664, 112) | (4736, 80) | 90 → 150 |
| 2 | 0〜3328 | 1024 | (80, 576) | (1152, 576) | 150 → 150 |
| 3 | 3584〜6400 | 4864 | (3632, 576) | (4992, 576) | 150 → 150 |
| 4 | 6656〜7168 | 6656 | (6736, 592) | (6784, 592) | 220 → 220 |
| 5 | 7424〜7680 | 7424 | (7472, 1616) | (7472, 1616) | 220 → 220 |
| 6 | 7936固定 | 7936 | (8024, 2624) | (7984, 2624) | 120 → 120 |

区間5はフラグによって異なる表を読むが、座標とタイマーは両方の表で同じ値だった。区間6ではカメラの下限・上限が境界と一致し、差し替えを行わない比較では開始表を選んだ。区間6の途中復帰座標は、境界を1だけ超える値を比較に渡した場合の結果。

MAME 0.289 の既定 DIP で、区間を読み込む前に `$72` を指定した。ページと復帰座標は ROM の値を使った。比較命令の直前でのみカメラ X を境界と同値（`equal`）または境界より1大きい値（`above`）に差し替えた。区間6の `equal` は実際のカメラ値を使った。タイマー減算（`$EC78`）でだけ残り値を1に差し替え、時間切れからの復帰を待った。全14条件をコールドブートから各2回実行し、条件ごとに `checkpoint_flow` 行が一致した。

```powershell

$env:REVG_CHECKPOINT_BOUNDARY = 'equal' # equal または above
& "$mameDir/mame.exe" makaimurg -rompath reference -noreadconfig -video none -sound none -nothrottle -skip_gameinfo -autoboot_delay 0 -autoboot_script tools/mame/measure-revg-checkpoint-flow.lua -cfg_directory build/revg-checkpoint-flow-cfg -nvram_directory build/revg-checkpoint-flow-nvram -snapshot_directory build/revg-checkpoint-flow-snap -seconds_to_run 40
Remove-Item Env:REVG_CHECKPOINT_SECTION, Env:REVG_CHECKPOINT_BOUNDARY
```

`start` と `reload` 行は、復帰フラグ、座標レコードのアドレス、ページ番号、座標 X・Y、タイマー初期値の順。アドレスとページ番号は16進数。`compare` 行は比較に渡した X、境界、カメラ X の下限と上限を示す。

## 終盤の分岐

- 区間5の分岐値 `$73` は `$6C0C` で1に初期化する。武器の取得処理 `$E6AB` 系のうち `$E6FA` に分岐するものは、取得したオブジェクトの `- $0E` フィールドから1を引いた値を `$E702` で `$73` に書く。`$7129–$712D` は3を通常の鍵経路に通し、それ以外は `$716B` に送る。後者は `$7177` で表示を切り替えて240を設定し、カウントが0になると `$71BA` が区間4を書き、進行状態を初期化へ戻す。
- 区間6で `$7F=0` のとき、`$71=1` なら `$71CE` で区間0へ戻る。それ以外では `$7254` 系で演出を更新し、`$7272` がカウント300を設定する。カウント終了時に `$7298` と `$729A` が `$7F` と `$71` を1にしてから、`$729C` で区間0へ戻る。
- 区間6で `$7F=1` のとき、`$7D3F` 系が演出を進め、`$7E1A` で `$7F=2` を書く。次の更新から `$71EF` 系が540、420、180の順にカウントを設定する。最後は `$724D–$724F` で `$71` と `$7F` をクリアし、`$729C` で区間0へ戻る。

MAME 0.289 の既定 DIP で、区間を読み込む直前に `$72` を5または6に設定した。読み込み後、進行状態 `$08=2`、演出状態 `$0B=$0E=0` を書き、各条件に合わせて `$71` と `$7F` を設定した。`$73` は初期値1のまま。以降の状態更新とカウントは ROM の処理を観測した。武器取得による `$73` の変化は、別の試行で照合した。[区間5の武器と進路](#区間5の武器と進路)

| 試行 | 開始時の `$71` / `$7F` | フレームログで確認した更新 |
| --- | --- | --- |
| `retry` | 0 / 0 | 1059に240を設定し、1299に区間5→4。 |
| `loop` | 0 / 0 | 1059に300を設定し、1358に区間6→0。両フラグは1。 |
| `restart` | 1 / 0 | カウントを設定せず、1059に区間6→0。 |
| `ending` | 1 / 1 | 1126に `$7F=2`。1127、1666、2085に順に540、420、180を設定し、2264に区間6→0。両フラグは0。 |

区間6のカウント処理は、値を設定した更新内で最初の1減算も実行する。このためログ上は300の設定から区間更新まで299フレーム、終了演出でも各カウント値より1フレーム短い間隔になる。

```powershell

& "$mameDir/mame.exe" makaimurg -rompath reference -noreadconfig -video none -sound none -nothrottle -skip_gameinfo -autoboot_delay 0 -autoboot_script tools/mame/measure-revg-late-flow.lua -cfg_directory build/revg-late-flow-cfg -nvram_directory build/revg-late-flow-nvram -snapshot_directory build/revg-late-flow-snap -seconds_to_run 51
```

`late` 行を試行ごとに照合する。`advance` は区間番号を書き込んだ時点で、その行の最後の2列は `$71`、`$7F`。`done` は設定されたカウントの個数を示す。コールドブートから各試行を2回実行し、試行ごとに計測行が一致した。

## 区間5の武器と進路

### 出現と取得

- 対象の敵が生成されると `$EAEC` 系が `$B0` を1減らす。区間初期化時と0になった時点に6を設定する。0になったときにアイテム枠 `$15E2` の `-$10` が空なら、生成した敵へのポインタを `$15F0` に保存し、`$EB1F–$EB33` が種類を選ぶ。枠が使用中ならカウントだけを6に戻す。
- `$7D` はアイテム枠を確保したときに進む0〜6の選択番号で、7に達すると0に戻る。`$EB34` の分岐表は2または6を `$EB51` の武器選択に通す。`$EB7B` は区間別の増分を `$78–$7C` に加えて桁上がりのマスクを作る。`$EB51` は現在の `$73` に対応するビットを除き、候補が生じるまで加算を繰り返す。最上位側の候補を種類1〜5に変換する。区間5の種類4に対応する `$7B` の増分は `$80`。
- `$E5CE` 系が敵の位置を基準にアイテムの座標を更新する。敵の状態が2になると、アイテムは `$E624` 系の落下に進む。接地後は `$E678` 系で表示を切り替えて取得可能になる。
- `$E6AB` はアイテム `-$0F` が非ゼロかつ `$0500` の下位ビットが1のとき、ワールド座標の差を X、Y の順に調べる。範囲は両軸とも±8 px。種類4はバンク4の表 `$5C20` を通って `$E6FA` に進み、`$E702` が `$73=3` を書く。ボス戦後の `$7129–$712D` はこの値で鍵の経路を選ぶ。

### MAME での照合

MAME 0.289 の既定 DIP で、区間読み込み前に `$72=5` を選んだ。読み込み後に `$7D=1`、`$7B=$80` を設定し、カウント `$B0` は初期値6から ROM の処理で進めた。通知4770で種類4が選ばれ、保持する敵のポインタは `$0CB0` だった。通知4996にアイテム処理が読む敵の状態だけを1から2へ差し替え、ROM の落下・接地処理を経て通知5038に取得判定へ進んだ。

取得判定に渡すプレイヤー座標の読み出しだけを変え、アイテム座標との差を以下の値にした。判定後に `$08=2`、`$0B=$0E=0` を設定してボス撃破後の処理に入り、`$73` は取得判定が残した値のまま通知5041の分岐を観測した。

| 試行 | 座標差 X / Y (px) | `$73` | 通過した分岐 |
| --- | --- | --- | --- |
| `inside` | +8 / +8 | 1→3 | `$712F` の鍵経路 |
| `outside-x` | +9 / +8 | 1 | `$716B` の戻り経路。Y 比較には到達しない。 |
| `outside-y` | +8 / +9 | 1 | `$716B` の戻り経路。Y 比較で範囲外になる。 |

```powershell

$env:REVG_WEAPON = 'inside' # outside-x、outside-y も指定可
& "$mameDir/mame.exe" makaimurg -rompath reference -noreadconfig -video none -sound none -nothrottle -skip_gameinfo -autoboot_delay 0 -autoboot_script tools/mame/measure-revg-weapon.lua -cfg_directory build/revg-weapon-cfg -nvram_directory build/revg-weapon-nvram -snapshot_directory build/revg-weapon-snap -seconds_to_run 94
Remove-Item Env:REVG_WEAPON
```

コールドブートから各条件を2回実行し、条件ごとに `weapon` 行が一致した。この試行の観測範囲は、指定した出現順での種類選択から撃破後の分岐入口まで。

## 区間6のボス消滅と周回

1. 区間読み込み時に `$6E43` 系がバンク2のポインタ `$4B18` を参照し、`$4FD9` の1件を敵スロットへ登録する。種別は `$0D`。敵更新 `$9F0C` 系はバンク4の表 `$472C` から `$DA21` に分岐する。初期化 `$DA65` はスロットの `+$16` に耐久値10を書き、命中時の `$EF28` はこの値を減らす。
2. 最終弾の命中後は、`$EF3C–$EF43` がスロットの `-$10` の値を左にシフトし、主状態 `-$0D` を2、補助状態 `-$0C` と `-$0B` を0にして消滅処理へ移す。初回更新 `$DCBB` は効果音コマンド `$3F`、`$07`、`$08` に続けて、`$7F=0` なら `$1C`、それ以外なら `$32` をキューに積む。
3. 共通処理 `$E818` を経て、`$DCBB` の初回更新から22フレーム後に `$DCD4` へ進む。`$7F=0` なら表示データのポインタ `$E890`、それ以外なら `$E894` を使い、初回更新で設定した63のカウントを減らし始める。カウントが0になると次の更新の `$DCEB` がスロットを無効にし、`$E78C` が残数 `$B6` を1から0に減らす。同じ更新で `$E79B` が進行状態 `$08=2` を書き、次回の進行更新が区間6の分岐を判定する。

MAME 0.289 の既定 DIP で、区間の読み込み前に `$72=6` を指定した。ボスが初期化されたらスロットに最終弾相当の消滅状態を設定し、その後は ROM の更新を計測した。コントローラーでのボス到達と命中はこの試行の対象外。開始演出で `$7AA2` が `$71=1` を書くため、`loop-ending` の初回だけ `$71=0` に設定した。2回目は区間0の読み込み直前に区間6を再指定し、1回目が書いた `$71` と `$7F` を引き継いだ。進行状態 `$08` はボス消滅処理が更新した。

| 試行 | 消滅開始時の `$71` / `$7F` | 消滅開始 → 表示切替 → 残数0 | 区間0へ戻るまで |

| `loop-ending` 2回目 | 1 / 1 | 1787 → 1809 → 1872 | 1926に `$7F=2`。カウント540、420、180を経て3064に区間0へ。`$71=$7F=0`。 |

## 区間別のボス残数と耐久値

`$6ED8` 系は区間番号で `$6ED1` の7バイトを引き、進行に必要なボス残数を `$B6` に設定する。プレイヤーの弾が命中したとき、`$EF1D–$EF28` は種類ごとに `$EF7A` のオフセット表を引き、該当するスロットの耐久値を1減らす。表の耐久値は各初期化ルーチンが書いた値。

| 区間 | 残数 `$B6` | 対象の種類と初期耐久値 | 出現元 |
| --- | --- | --- | --- |
| 0 | 1 | `$08` ×1、各10 | ページ `$0C` → グループ表 `bank2:$50D0` → 配置表 `$5681` |
| 1 | 2 | `$08` ×2、各10 | ページ `$1A` → `bank2:$50F1` → `$5688` |
| 2 | 1 | `$0C` ×1、頭6・残り8部位は各1 | ページ `$4C` → `bank2:$5136` → `$57FD` |
| 3 | 1 | `$0C` ×1、頭6・残り8部位は各1 | ページ `$58` → `bank2:$5146` → `$57FD` |
| 4 | 1 | `$06` ×1、各4 | 区間読み込み時の固定配置表 `bank2:$4EDF` |
| 5 | 2 | `$06` ×2、各4 | 区間読み込み時の固定配置表 `bank2:$4F6B` |
| 6 | 1 | `$0D` ×1、10 | 区間読み込み時の固定配置表 `bank2:$4FD9` |

- `$06` の耐久値はスロットの `+$14` にあり、`$BD6D` が4を書く。`$08` と `$0D` は `+$16` を使い、それぞれ `$C408` と `$DA65` が10を書く。消滅時は `$06` が `$C253`、`$08` が `$CB2B`、`$0D` が `$DCFD` から残数更新 `$E78C` へ進む。
- `$0C` の耐久値は `+$10` にある。`$D4DC` が頭に6を書き、`$D501–$D564` が胴7つと尾1つを別スロットに登録する。`$D5BF` と `$D604` が胴と尾にそれぞれ1を書く。頭の撃破経路で `$D9BA` がスロットの `+$0B` を1にし、後始末 `$DA07` がその値を調べて残数更新へ進む。
- 区間5の開始ページ `$DD` では `bank2:$5170` のグループから `$08` と `$0C` も出現する。両方の初期耐久値を実測した。消滅時は `$CB25` と `$DA17` が区間5かどうかを調べ、区間5では残数更新をスキップする。

MAME 0.289 の既定 DIP で、区間の読み込み前に `$72` を指定した。区間0〜3だけは開始表から読み取るページ番号を上表の値に差し替え、通常の出現処理を通した。区間4〜6では既定の開始ページを使った。全7区間をコールドブートから各2回実行し、区間ごとに `boss_roster` 行が一致した。撃破時の残数更新経路は逆アセンブルで特定した。

```powershell
$mameDir = "$env:USERPROFILE/tools/mame/mame0289"
$env:REVG_BOSS_SECTION = '2' # 0〜6を指定
& "$mameDir/mame.exe" makaimurg -rompath reference -noreadconfig -video none -sound none -nothrottle -skip_gameinfo -autoboot_delay 0 -autoboot_script tools/mame/measure-revg-boss-roster.lua -cfg_directory build/revg-boss-roster-cfg -nvram_directory build/revg-boss-roster-nvram -snapshot_directory build/revg-boss-roster-snap -seconds_to_run 22
Remove-Item Env:REVG_BOSS_SECTION
```

`hp` 行は、書き込み直後の PC、スロット基準アドレス、種類、亜種、耐久値のオフセット、初期耐久値の順。初期耐久値のみ10進数で出力する。[耐久値を保った区間1の撃破試行](revision-g.md#通常の耐久値でのボス戦)

## 複数部位ボスの被弾と消滅

種別 `$0C` は部位を双方向リストで管理する。各スロットの `+$1C` が頭側、`+$1E` が尾側を指す。`$D577–$D585` が `+$1B` に部位番号を設定し、頭が8、胴が7〜1、尾が0になる。

- **胴の被弾。** `$EF28` が命中した胴の耐久値を1から0にする。`$D968–$D982` はその部位から尾までたどり、命中した部位を生存状態に戻して耐久値を1に戻す。`$D983–$D99B` は尾の一つ手前を新しい末端にし、旧末端を消滅処理に送る。区間2で番号4の胴に1発当てると、番号1だった部位が新しい尾になり、旧末端だけが消滅した。残数 `$B6` は1のままだった。
- **頭の撃破。** 6発目で耐久値が0になると、`$D99C–$D9B2` がリンクをたどって残った部位を消滅処理に送り、頭は別の消滅処理に入る。`$D9BA` が頭の `+$0B` を1にし、`$D9C6` が他の部位では0にする。両区間で最後の命中から88フレーム後に頭が消滅した。

| 区間 | 頭の消滅後に計測した状態 |
| --- | --- |
| 2 | `$DA17` から `$E78C` に進み、`$B6` が1から0、進行状態 `$08` が2になった。切り替わった時点で残る7部位は消滅演出中だった。 |
| 5 | `$DA17` の区間判定で `$E78C` を通らず、`$B6=2`、`$08=1` を維持した。頭の消滅から15フレーム後に残る8部位も消滅した。 |

MAME 0.289 の既定 DIP で、区間の読み込み前に区間番号を指定した。区間2だけ開始ページを `$4C` に変え、区間5は既定の `$DD` を使った。射撃はボタン入力で行った。画面外にいる狙った部位に命中させるため、弾の衝突処理中に限って対象選別（`$EEA8`）と弾座標の読み出し（`$EEFA`、`$EF05`）を差し替えた。耐久値の減算、部位の状態遷移、残数と進行の更新は ROM の処理を通した。区間ごとにコールドブートから2回実行し、`boss_parts` 行が一致した。

```powershell
$mameDir = "$env:USERPROFILE/tools/mame/mame0289"
$env:REVG_BOSS_SECTION = '2' # 2または5を指定
& "$mameDir/mame.exe" makaimurg -rompath reference -noreadconfig -video none -sound none -nothrottle -skip_gameinfo -autoboot_delay 0 -autoboot_script tools/mame/measure-revg-boss-parts.lua -cfg_directory build/revg-boss-parts-cfg -nvram_directory build/revg-boss-parts-nvram -snapshot_directory build/revg-boss-parts-snap -seconds_to_run 32
Remove-Item Env:REVG_BOSS_SECTION
```

`hit` 行は部位、スロット基準アドレス、命中直後の耐久値を示す。`remove` 行はスロット基準アドレス、`+$0B` の値、消滅時点のボス残数を示す。`done` 行には試行全体の消滅数、最終ボス残数、進行状態を出力する。スロット基準アドレスのみ16進数。

## 次に参照する処理

| 位置 | 種別 | 用途と根拠 |
| --- | --- | --- |
| fixed:`$E3E5–$E3EC`、`$E3ED–$E3F0` | コード、ジャンプ先テーブル | 種別 `$03` はバリアントで `$E3CA` または `$E3F1` に分岐する。今回の種別 `$04` の足場では移動指示の読み出しを計測した。 |

## 再現手順

```powershell
$mameDir = "$env:USERPROFILE/tools/mame/mame0289"
python tools/mame/disassemble-revg.py --unidasm "$mameDir/unidasm.exe"
& "$mameDir/unidasm.exe" build/revg-disassembly/fixed.bin -arch m6809 -basepc 0x65c4 -skip 0x5c4 -count 0xc -lower
& "$mameDir/mame.exe" makaimurg -rompath reference -noreadconfig -video none -sound none -nothrottle -skip_gameinfo -autoboot_delay 0 -autoboot_script tools/mame/measure-revg-rom-map.lua -cfg_directory build/revg-rom-map-cfg -nvram_directory build/revg-rom-map-nvram -seconds_to_run 22
```

生成スクリプトは3個の ROM メンバーを MAME の SHA-1 と照合し、固定領域と5バンクの `.bin` と `.asm` を Git 管理外の `build/revg-disassembly/` に出力する。上の `unidasm` の例では、ファイル内の `0x5c4` を飛ばし、出力と相対分岐の基準を CPU アドレス `0x65c4` に置く。

MAME のログでは `bank_select` が書き込み値とバンク、`vector_read` がベクタの読み出し、`irq_dispatch` がテーブルで参照された分岐先を示す。ログの PC はタップ時点の値で、例えば `$6073` の書き込みは `$6076` で報告される。電源投入からの2回の実行で、速度表示を除くログが一致した。
