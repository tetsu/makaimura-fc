## 2. スコア・エクステンド（1UP）・HUD 規約

### 2.1 スコア加算表（100点単位で管理、HUD 6桁表示 `000000`）

| イベント | 加算点 | 内部加算値 (`ap_add_score` 引数) |
| --- | ---: | ---: |
| ゾンビ撃破 | 100 | `1` |
| 固定敵・ツボ持ち敵・固定砲台撃破 | 200 | `2` |
| 武器・鎧アイテム取得 | 100 | `1` |
| ボス鍵取得 | 500 | `5` |
| ボス撃破 | 1,000 | `10` |

### 2.2 エクステンド（1UP）規約
- 新規ゲーム開始時（タイトルから Right+START）：スコア `000000`、残機 `3`、次回エクステンド目標を **2,000点**（内部値 `20`）に設定。
- スコアが目標に達すると残機を `+1`（上限 `9`）、SE（`snd_se_key`）を再生し、次回目標を **+5,000点**（内部値 `+50`、すなわち 2,000 → 7,000 → 12,000 ...）に更新する。
- ミス復帰・ステージ移行時はスコアとエクステンド目標を引き継ぐ。タイトル復帰またはゲームオーバー後の新規開始時にリセットする。
- 全7区間完成時（Task 4-3/4-4）にアーケード準拠の 20,000 / 70,000 点へ調整可能な定数設計とする。

### 2.3 アーケードモード HUD レイアウト（固定上端4行）
- Row 1 (`$2023`): `STG # LIFE # TIME ### CP # W`（`W` = 武器 `L`/`D`/`T`）
- Row 2 (`$2043`): `SCORE ######`（6桁、下2桁 `00` 固定）

## 3. `$8000` ステージバンク共通バイナリ仕様

各ステージバンク（`BANK12+`）は既存 `stage_header`（`$8001..$8012`）とパレット表を維持したまま、固定アドレス **`$8080`** にアーケードステージ記述子（`arcade_stage_desc`）を配置する。`BANK3`（`$A000`）はこの固定オフセットを直接参照することで、ステージ番号のハードコード分岐なしに全ステージを駆動する。

### 3.1 縦複数ページマップ配置規約
- `map_col_stride = 16`（1列16メタタイル = 256 px）を維持する。
- 縦2ページステージ（`stage_width_cols = 16`, `stage_height_rows = 30` = 480 px）では、`read_map_cell` が `row >= 16` のときに自動で `col += stage_width_cols`, `row -= 16` へ変換する。
  - 縦ページ 0（`row 0..15`, world Y `0..255`）: マップ先頭 16 列（256 B）
  - 縦ページ 1（`row 16..29`, world Y `256..479`）: マップ後半 16 列（256 B）
